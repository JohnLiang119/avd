# config-persistence Specification

## Purpose
提供跨平台（Windows Tauri 與 Android Capacitor）一致的設定持久化能力，讓應用程式的偏好設定與追蹤清單在重啟後正確還原，並將平台差異收斂於單一儲存埠，使還原過程不受多重來源的執行時序影響。

## Requirements
### Requirement: 單一真相來源的設定持久化

系統 MUST（必須）透過單一儲存介面讀寫所有設定值，該介面在各平台上 MUST（必須）僅有一個權威來源。系統 MUST NOT（不得）同時維護兩份可獨立寫入的設定副本，也不得讓還原結果取決於哪一份先被讀取。

#### Scenario: 寫入設定後重新啟動

- **WHEN** 使用者變更任一設定項（例如 MP3 模式、Wi-Fi 資訊、刪除確認開關）後關閉並重新啟動應用程式
- **THEN** 系統還原出的設定值與關閉前一致
- **AND** 還原結果在 Windows 與 Android 上表現相同

#### Scenario: 啟動還原期間的寫入

- **WHEN** 應用程式啟動、設定尚在還原過程中，此時發生設定寫入
- **THEN** 該次寫入 MUST NOT（不得）被後續完成的還原流程覆蓋

#### Scenario: 儲存來源為空或損毀

- **WHEN** 儲存來源不存在、內容為空、或 JSON 解析失敗
- **THEN** 系統以各設定項的預設值啟動，不中斷應用程式初始化，並於主控台記錄錯誤

### Requirement: 平台差異收斂於儲存埠

設定的讀寫介面 MUST（必須）與平台判斷解耦；呼叫端 MUST NOT（不得）為了持久化而自行判斷執行平台。新增一個設定項時 MUST（必須）只需在單一處宣告，不得要求同步修改多份型別對照表或鍵名白名單。

#### Scenario: 新增一個布林設定項

- **WHEN** 開發者新增一個布林型別的設定項
- **THEN** 只需在單一處宣告該設定項的鍵名與預設值，即可在兩個平台上正確持久化與還原
- **AND** 不需要修改任何鍵名白名單或型別轉換分支

#### Scenario: 呼叫端讀寫設定

- **WHEN** 應用程式任一處需要讀取或寫入設定
- **THEN** 該處呼叫統一的儲存介面，程式碼中不出現平台判斷分支
