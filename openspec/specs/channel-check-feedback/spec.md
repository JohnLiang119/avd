# channel-check-feedback Specification

## Purpose
頻道檢查完成後，依據實際的成功與失敗狀態，給予使用者誠實且準確的回饋訊息，避免假陽性的「沒有新影片」誤導。

## Requirements

### Requirement: 頻道檢查結果須區分成功與失敗狀態

當使用者按下「立即檢查」、對單一頻道執行檢查或模擬新片測試，或自動排程觸發檢查時，系統 MUST（必須）追蹤每個頻道的抓取結果（成功或失敗），並依據結果顯示不同的 Toast 訊息。

檢查結果訊息 MUST（必須）由下列三個計數唯一決定，且此三個計數 MUST（必須）互斥、不重複計算同一支影片：

- **已建立任務數（N）**：本輪實際建立下載任務的影片數。
- **關鍵字篩除數（K）**：本輪符合既有新片條件（發布時間晚於該頻道時間錨點，且尚未存在於下載佇列），但因未命中該頻道任一有效關鍵字而未建立下載任務的影片數。
- **失敗頻道數（M）**：本輪抓取失敗的啟用頻道數。

「發現 N 部新影片」中的 N MUST（必須）只計入實際建立下載任務的影片數；被關鍵字篩除的影片、命中關鍵字但因直播／首播或狀態未知而未處理的影片，以及因佇列去重而未建立任務的影片，MUST NOT（不得）計入 N。

當 K 大於零時，系統 MUST NOT（不得）顯示「目前沒有新影片」，MUST（必須）改以明確區分的訊息告知「本輪有影片符合既有新片條件，但全部（或部分）不符合關鍵字設定」，避免產生本能力所要防止的假陽性誤導。

#### Scenario: 全部頻道成功且無新影片

- **WHEN** 所有啟用的頻道都成功抓取，且未發現任何符合既有新片條件的影片（N 為 0 且 K 為 0）
- **THEN** 系統顯示「已檢查完成，目前沒有新影片」

#### Scenario: 全部頻道成功且有新影片

- **WHEN** 所有啟用的頻道都成功抓取，且實際建立下載任務的影片數 N 大於零，且沒有任何影片被關鍵字篩除（K 為 0）
- **THEN** 系統顯示「🔔 發現 N 部新影片，已優先加入下載佇列！」

#### Scenario: 部分頻道失敗且有新影片

- **WHEN** 部分頻道抓取失敗，但其他成功的頻道實際建立下載任務的影片數 N 大於零，且沒有任何影片被關鍵字篩除（K 為 0），失敗數為 M
- **THEN** 系統顯示「🔔 發現 N 部新影片，已加入佇列！（⚠️ M 個頻道無法連線）」

#### Scenario: 部分頻道失敗且無新影片

- **WHEN** 部分頻道抓取失敗，成功的頻道沒有任何符合既有新片條件的影片（N 為 0 且 K 為 0），失敗數為 M
- **THEN** 系統顯示「已檢查完成，目前沒有新影片（⚠️ M 個頻道無法連線）」

#### Scenario: 全部頻道失敗

- **WHEN** 所有啟用的頻道都抓取失敗
- **THEN** 系統顯示「❌ 無法連線至 YouTube，請稍後再試」

#### Scenario: 全部頻道成功但新影片全部被關鍵字篩除

- **WHEN** 所有啟用的頻道都成功抓取，本輪有 K 部影片符合既有新片條件但全部未命中關鍵字（K 大於零且 N 為 0）
- **THEN** 系統顯示「已檢查完成：本輪有 K 部新影片，但都不符合關鍵字設定，未加入佇列」
- **AND** 系統 MUST NOT（不得）顯示「已檢查完成，目前沒有新影片」
- **AND** 該訊息 MUST（必須）與「目前沒有新影片」在文字上可明確區分，使使用者能辨別是「沒有新片」還是「新片被自己的關鍵字篩掉」

#### Scenario: 部分頻道失敗且新影片全部被關鍵字篩除

- **WHEN** 部分頻道抓取失敗（失敗數為 M），成功的頻道本輪有 K 部影片符合既有新片條件但全部未命中關鍵字（K 大於零且 N 為 0）
- **THEN** 系統顯示「已檢查完成：本輪有 K 部新影片，但都不符合關鍵字設定，未加入佇列（⚠️ M 個頻道無法連線）」
- **AND** 系統 MUST NOT（不得）以「部分頻道失敗且無新影片」或「全部頻道成功但新影片全部被關鍵字篩除」的訊息覆蓋此組合，兩項條件 MUST（必須）同時在同一則訊息中呈現

#### Scenario: 部分影片命中、部分被關鍵字篩除

- **WHEN** 本輪同時存在實際建立下載任務的影片（N 大於零）與被關鍵字篩除的影片（K 大於零）
- **THEN** 系統 MUST（必須）採用「發現 N 部新影片」的訊息分支，並 MUST（必須）在同一則訊息內附加說明另有 K 部影片不符合關鍵字設定
- **AND** N MUST（必須）只計入實際建立下載任務的影片數，MUST NOT（不得）把被篩除的 K 部影片計入 N
- **AND** 若同時有 M 個頻道抓取失敗，該則訊息 MUST（必須）保留既有的「⚠️ M 個頻道無法連線」提示

#### Scenario: 未建立任務的其他原因不得計入關鍵字篩除數

- **WHEN** 某支符合既有新片條件的影片已命中關鍵字，但因為直播中、預定首播、狀態未知或已存在於下載佇列而未建立下載任務
- **THEN** 系統 MUST NOT（不得）將該影片計入關鍵字篩除數 K，亦 MUST NOT（不得）計入已建立任務數 N
- **AND** 此類影片 MUST NOT（不得）觸發「不符合關鍵字設定」的訊息，其回饋 MUST（必須）沿用既有的成功／失敗訊息分支

#### Scenario: 所有頻道皆未設定關鍵字時回饋不變

- **WHEN** 本輪檢查涵蓋的頻道皆未設定有效關鍵字
- **THEN** 關鍵字篩除數 K MUST（必須）恆為 0
- **AND** 系統顯示的訊息 MUST（必須）與導入關鍵字篩選前的成功／失敗五種情境完全一致

#### Scenario: 訊息分支互斥且不互相覆蓋

- **WHEN** 一輪檢查結束並需要產生回饋訊息
- **THEN** 系統 MUST（必須）依 N、K、M 三個計數選出且僅選出一則檢查結果訊息
- **AND** 系統 MUST NOT（不得）同時顯示兩則以上互相矛盾的檢查結果訊息（例如同時顯示「目前沒有新影片」與「發現 N 部新影片」），也 MUST NOT（不得）讓後續訊息覆蓋掉關鍵字篩除的告知

#### Scenario: 單一頻道檢查或模擬新片測試全部未命中關鍵字

- **WHEN** 使用者對單一頻道執行立即檢查或模擬新片測試，該頻道本輪取得的影片全部未命中其關鍵字設定
- **THEN** 系統 MUST（必須）顯示專用提示，明確告知該頻道本輪沒有影片符合關鍵字設定
- **AND** 系統 MUST NOT（不得）建立任何下載任務或測試任務
- **AND** 系統 MUST NOT（不得）以「目前沒有新影片」或抓取失敗類訊息取代該提示

#### Scenario: 備援來源候選視窗受限時的回饋

- **WHEN** 本輪影片由 yt-dlp 備援取得且取回筆數已達該來源每輪上限，其中符合既有新片條件的影片全部未命中關鍵字
- **THEN** 系統 MUST（必須）顯示「本輪新影片全部不符合關鍵字設定」的訊息，MUST NOT（不得）顯示「目前沒有新影片」
- **AND** 該訊息 MUST NOT（不得）暗示已檢視該頻道的全部新影片，因為本輪比對範圍僅限實際取回的影片
