## Purpose

提供跨平台（Windows 與 Android）的線上版本更新能力：於啟動時背景查詢 GitHub Releases 的最新版本，向使用者呈現更新內容並取得同意，下載對應平台的安裝檔並即時回饋進度，最後叫起系統原生安裝流程完成更新。
## Requirements
### Requirement: 更新內容展示與使用者同意
當檢測到新版本時，系統MUST（必須）向使用者清楚呈現版本更新內容，並在使用者點擊「立即更新」後持續保留彈窗以展示即時下載與安裝進度，不可因確認動作而提前關閉彈窗。

#### Scenario: 使用者點擊「立即更新」持續展示下載進度
- **WHEN** 使用者在更新提示對話框中點擊「立即更新」
- **THEN** 系統阻止對話框關閉，隱藏底部確認/取消按鈕，並在對話框內持續展示下載進度百分比與傳輸量

#### Scenario: 使用者點擊「稍後再說」
- **WHEN** 使用者在更新提示對話框中點擊「稍後再說」
- **THEN** 系統正常關閉對話框，不執行更新流程

#### Scenario: 下載完成準備安裝
- **WHEN** 安裝檔下載進度達到 100%
- **THEN** 系統對話框顯示「下載完成，正在喚起安裝...」並調用系統安裝介面

### Requirement: 啟動時背景靜默檢查版本
應用程式在啟動進入主介面時，系統 MUST（必須）在背景非同步向 GitHub Releases 查詢最新版本資訊，並且在無新版本或網路異常時保持靜默。

#### Scenario: 檢測到有新版本發布
- **WHEN** 應用程式啟動且 GitHub Releases 上的最新標籤版本（例如 v1.0.1）高於目前執行版本（例如 v1.0.0）
- **THEN** 系統彈出版本更新提示對話框，顯示新版本號、更新日誌說明，以及「稍後再說」與「立即更新」按鈕

#### Scenario: 遠端版本相同或更低
- **WHEN** 應用程式啟動且 GitHub Releases 上的版本等於或小於本機版本
- **THEN** 系統不彈出任何通知或對話框，使用者無感正常進入應用

#### Scenario: 網路連線失敗或超時
- **WHEN** 應用程式啟動時處於離線狀態或 GitHub API 請求超過 5 秒未回應
- **THEN** 系統靜默結束檢查，不中斷使用者操作也不顯示錯誤訊息

---

### Requirement: 跨平台安裝檔下載與進度反饋
系統 MUST（必須）根據目前運行平台（Android APK 或 Windows MSI）下載對應附件檔案，並即時回饋下載進度。

#### Scenario: Android 平台下載 APK
- **WHEN** 在 Android 裝置上開始更新
- **THEN** 系統自動解析 GitHub Release 附件中的 `AVD_*.apk` 檔案，下載至暫存目錄並展示 0% 到 100% 下載進度條

#### Scenario: Windows 平台下載 MSI
- **WHEN** 在 Windows 系統上開始更新
- **THEN** 系統自動解析 GitHub Release 附件中的 `AVD_*.msi` 檔案，下載至本機目錄並展示 0% 到 100% 下載進度條

#### Scenario: 下載失敗與異常處理
- **WHEN** 檔案下載過程中發生網路中斷或伺服器錯誤
- **THEN** 系統顯示下載失敗訊息，並提供「重試下載」與「在瀏覽器開啟下載」按鈕

---

### Requirement: 下載完成自動叫起安裝程式
安裝檔下載完畢後，系統 MUST（必須）自動觸發系統原生的安裝流程。

#### Scenario: Android 平台叫起系統安裝器
- **WHEN** APK 下載完成達到 100%
- **THEN** 系統自動透過 Android 原生 Intent 喚起系統套件安裝程式，彈出「是否要更新此應用程式」視窗供使用者確認安裝

#### Scenario: Windows 平台啟動 MSI 安裝器
- **WHEN** MSI 下載完成達到 100%
- **THEN** 系統自動執行 MSI 安裝程序並退出目前程式進行更新覆蓋

---

### Requirement: 設定頁手動檢查更新
系統 MUST（必須）在設定選單中提供手動檢查新版本的功能。

#### Scenario: 手動檢查且已是最新版本
- **WHEN** 使用者在設定面板點擊「檢查更新」且目前已是最新版本
- **THEN** 系統彈出 Toast 提示「目前已是最新版本 (v1.0.0)」
