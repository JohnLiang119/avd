## Purpose

規範下載檔案的命名規則與唯一性保證：檔名須能區分標題相同但實為不同的影片，且檔名碰撞絕不得使下載失敗。

## ADDED Requirements

### Requirement: 檔名須包含發布時間以保證唯一

下載檔案的名稱 MUST 由標題與該影片的發布時間共同組成。系統 MUST NOT 僅以標題作為檔名 —— 部分來源（如 TikTok、Douyin）的標題即描述文字，同一創作者的多支影片經常完全相同。

來源未提供發布時間時，系統 MAY 僅使用標題，此時唯一性由碰撞處置需求承接。

#### Scenario: 標題相同但發布時間不同的多支影片

- **WHEN** 使用者批次下載同一創作者多支標題完全相同、發布時間不同的影片
- **THEN** 每支影片各自存為一個檔案，檔名因發布時間而互異，且全部下載成功

#### Scenario: 來源未提供發布時間

- **WHEN** 某支影片的來源未提供可用的發布時間
- **THEN** 系統仍完成下載，檔名退回僅使用標題，並由碰撞處置確保不覆蓋既有檔案

### Requirement: 檔名碰撞不得使下載失敗

當目標檔名已被占用時，系統 MUST 自動改用一個未被占用的名稱完成下載。系統 MUST NOT 因檔名碰撞而中止下載或將任務標記為失敗，亦 MUST NOT 覆蓋既有檔案。

此行為 MUST 在 Windows 與 Android 兩端一致。

#### Scenario: 目標檔名已存在

- **WHEN** 一支影片的目標檔名與磁碟上既有檔案相同
- **THEN** 系統自動改用未占用的名稱存檔，下載成功，且既有檔案未被覆蓋

#### Scenario: 兩平台的一致性

- **WHEN** 同一批會產生檔名碰撞的影片分別在 Windows 與 Android 下載
- **THEN** 兩端皆自動改名並全數成功，不因平台而有一方失敗

### Requirement: 檔名碰撞屬確定性錯誤

若系統仍以錯誤形式回報檔名碰撞，該錯誤 MUST 被視為確定性錯誤而不自動重試，且 MUST NOT 向使用者顯示暗示問題為暫時性的重試次數。

#### Scenario: 回報檔名碰撞錯誤

- **WHEN** 下載因檔名碰撞而回報錯誤
- **THEN** 系統立即將該任務標記為失敗，不進行自動重試

### Requirement: 既有檔案不受命名規則變更影響

命名規則變更 MUST 只作用於新的下載。系統 MUST NOT 改名、移動或刪除磁碟上既有的檔案。

#### Scenario: 命名規則變更後首次下載

- **WHEN** 使用者在命名規則變更後下載新影片
- **THEN** 新檔案採用新命名規則，磁碟上先前下載的檔案維持原名不變
