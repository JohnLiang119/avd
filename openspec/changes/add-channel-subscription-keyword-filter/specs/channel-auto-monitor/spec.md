## MODIFIED Requirements

### Requirement: Channel Subscription & Management
系統 MUST（必須）允許使用者手動輸入 YouTube 頻道網址或 Handle 解析出資訊，提供視覺化追蹤清單，並支援個別頻道狀態切換、刪除，以及個別頻道的影片標題關鍵字篩選設定（新增、移除與全部清空）。當使用者在主畫面上方的網址列直接輸入頻道網址時，系統也 MUST（必須）檢查該頻道是否在追蹤清單內，若不在則 MUST（必須）主動詢問使用者是否要加入追蹤。

不論頻道訂閱是由追蹤清單管理介面新增、由主畫面網址列確認加入追蹤，或由備份還原匯入而建立，系統 MUST（必須）以同一組關鍵字正規化規則產生該頻道的關鍵字清單；任一建立入口 MUST NOT（不得）寫入未經正規化的關鍵字。

#### Scenario: User manages subscriptions
- **WHEN** 使用者在專屬追蹤清單介面輸入頻道網址或管理追蹤清單
- **THEN** 系統更新本地持久化儲存 (`localStorage`) 的追蹤狀態

#### Scenario: User pastes a channel URL in the main input field and confirms tracking
- **WHEN** 使用者在主畫面輸入頻道網址或 Handle，且該頻道不在追蹤清單內，並在提示視窗中選擇「加入追蹤並下載」
- **THEN** 系統將該頻道加入追蹤清單 (`localStorage`)，並繼續執行該頻道的單次下載任務
- **AND** 系統將該頻道的關鍵字清單建立為空清單，使其維持既有全量追蹤行為，直到使用者另行設定關鍵字

#### Scenario: User pastes a channel URL in the main input field and declines tracking
- **WHEN** 使用者在主畫面輸入頻道網址或 Handle，且該頻道不在追蹤清單內，並在提示視窗中選擇「僅下載」
- **THEN** 系統不修改追蹤清單，直接執行該頻道的單次下載任務

#### Scenario: 使用者管理個別頻道的關鍵字
- **WHEN** 使用者在追蹤清單介面為某個頻道新增、移除或全部清空影片標題關鍵字並確認儲存
- **THEN** 系統以正規化後的關鍵字清單更新該頻道的持久化訂閱資料，且 MUST NOT（不得）影響其他頻道的關鍵字設定
- **AND** 使用者取消編輯時，系統 MUST NOT（不得）改變該頻道原有的關鍵字清單

#### Scenario: 三個頻道建立入口套用相同關鍵字正規化
- **WHEN** 同一組關鍵字文字分別經由追蹤清單管理介面新增頻道、網址列確認加入追蹤，或備份還原匯入而寫入頻道訂閱
- **THEN** 三個入口產生的有效關鍵字清單與其顯示文字 MUST 完全一致
- **AND** 任一入口 MUST NOT（不得）以自訂規則另行處理空白、重複項目或字形差異

### Requirement: Periodic Check & New Video Matching

系統 MUST 支援每 60 分鐘自動或手動執行頻道輪詢，透過 YouTube 官方 RSS 並以影片實際發布時間判定新影片 (`publishedTime > lastPublishedTime`)。

新影片的判定 MUST（必須）同時滿足下列三個條件：「發布時間晚於該頻道的時間錨點」、「尚未存在於下載佇列」，以及「影片標題命中該頻道的關鍵字篩選」。當該頻道未設定任何有效關鍵字時，第三個條件 MUST（必須）視為自動滿足，維持既有全量追蹤行為。頻道首次被追蹤時，系統 MUST（必須）僅初始化時間錨點而不建立任何下載任務。時間錨點 MUST NOT（不得）在缺少精確發布時間的情況下被推進至當下時間。

時間錨點的推進 MUST（必須）受下列上限守門。本輪若存在任何「未處理影片」（已命中關鍵字篩選，但因屬直播、首播或狀態未知而未建立下載任務者），錨點 MUST NOT（不得）晚於所有未處理影片中最早的發布時間；未命中關鍵字篩選的影片 MUST NOT（不得）被列為未處理影片，錨點得以越過。此外，本輪取回筆數已達該資料來源每輪候選上限時（備援來源每輪 2 筆、官方 RSS 約 15 筆），代表可能存在未被取回也未經比對的較舊影片，錨點 MUST NOT（不得）晚於本輪實際取回影片中最舊者的發布時間。

#### Scenario: Auto and manual checking

- **WHEN** 系統啟動且距離上次檢查超過 60 分鐘，或使用者點擊手動檢查
- **THEN** 系統解析 RSS 並比對影片實際發布時間篩選出新發布的影片，再以該頻道的關鍵字篩選決定哪些影片可建立下載任務
- **AND** 系統依上述錨點上限守門規則更新該頻道的時間錨點與最新已知影片識別，MUST NOT（不得）無條件將錨點設為本輪最新影片的發布時間

#### Scenario: First time channel subscription anchor

- **WHEN** 使用者剛新增追蹤頻道或頻道首次執行檢查（`lastPublishedTime` 與 `lastCheckTime` 皆無值）
- **THEN** 系統將該頻道目前最新影片的發布時間與 ID 設為起始基準錨點，不觸發歷史影片下載
- **AND** 若該最新影片不帶精確發布時間，系統不建立錨點，維持未初始化狀態待下次檢查
- **AND** 不論該最新影片是否命中該頻道的關鍵字篩選，首次錨點皆以本輪取回的最新影片建立

#### Scenario: 影片已存在於下載佇列

- **WHEN** 某支影片的發布時間晚於錨點，但佇列中已有相同影片 ID 的任務
- **THEN** 系統不重複建立任務
- **AND** 去重比對涵蓋扁平任務，以及頻道群組底下播放清單的巢狀子任務

#### Scenario: 取得精確發布時間時推進錨點

- **WHEN** 本次檢查有影片被實際處理，且其帶有精確發布時間
- **THEN** 系統將該頻道的時間錨點更新為已處理影片中最新者的發布時間
- **AND** 若本輪存在未處理影片，推進後的錨點 MUST NOT（不得）晚於所有未處理影片中最早的發布時間

#### Scenario: 缺少精確發布時間時保留錨點

- **WHEN** 檢查取得的最新影片不帶精確發布時間（例如備援通道未回傳時間欄位）
- **THEN** 系統保留該頻道原有的時間錨點不變
- **AND** 不以當下時間推進錨點，避免基準被推至未來而導致後續永久漏片

#### Scenario: 未命中關鍵字的影片可被錨點越過

- **WHEN** 本輪符合「發布時間晚於錨點」與「尚未存在於下載佇列」的影片中，有一支或多支未命中該頻道的關鍵字篩選，且其餘影片皆已處理完成
- **THEN** 系統 MUST 依既有精確發布時間安全規則推進錨點，未命中影片 MUST NOT（不得）成為錨點上限
- **AND** 後續輪詢 MUST NOT（不得）再次比對或重複處理已被錨點越過的未命中影片

#### Scenario: 未處理影片阻止較新未命中影片推過錨點

- **WHEN** 本輪同時出現「較舊、已命中關鍵字，但因屬直播、首播或狀態未知而未建立任務」的影片，以及「較新但未命中關鍵字」的影片
- **THEN** 系統 MUST 以該未處理影片的發布時間作為錨點上限，錨點 MUST NOT（不得）被較新的未命中影片推過該時間
- **AND** 下一輪檢查 MUST 仍能重新評估該未處理影片，並在其成為可下載內容時建立下載任務

#### Scenario: 候選視窗達上限時限制錨點推進

- **WHEN** 本輪影片清單取回筆數已達該資料來源每輪的候選上限（例如備援來源每輪僅取回 2 筆）
- **THEN** 系統 MUST NOT（不得）將錨點推進至晚於本輪實際取回影片中最舊者的發布時間
- **AND** 系統 MUST NOT（不得）因本輪影片全部未命中關鍵字而越過本輪未被取回、亦未經比對的較舊影片

#### Scenario: Display latest publish time on channel card

- **WHEN** 使用者檢視已追蹤頻道清單
- **THEN** 系統在各頻道卡片上展示該頻道最新影片之發布時間格式化資訊

#### Scenario: Task title with publish time on main queue

- **WHEN** 系統將任何影片建立、進行下載或完成為下載任務並於主畫面佇列呈現（包含使用者手動單一加入、自動追蹤或播放清單解析）
- **THEN** 系統產生的任務標題（抬頭）在排隊、下載中與完成後始終穩定包含該影片之發布時間格式化資訊 (YYYY/MM/DD HH:mm:ss)，不因進度更新或下載完成事件而遺失

#### Scenario: 新影片以優先順序加入佇列

- **WHEN** 篩選出一支或多支同時滿足三項新片判定條件（含命中關鍵字篩選）的影片
- **THEN** 系統為每支通過關鍵字篩選的影片建立下載任務，任務標題包含頻道名稱前綴與發布時間，並依來源標記為 RSS 或 yt-dlp 備援
- **AND** 任務的子資料夾名稱以頻道名稱產生，且已移除檔案系統不接受的字元
- **AND** 系統 MUST NOT（不得）為未命中關鍵字篩選的影片建立下載任務

### Requirement: Priority Insertion & Automatic Download
系統MUST（必須）將偵測到且通過該頻道關鍵字篩選的新影片建立為 MP4 高畫質任務並插入下載佇列最前面 (`tasks.unshift`)，若當前無任務則自動開始下載，並更新檢查時間。未通過關鍵字篩選的影片 MUST NOT（不得）被建立任務、插入佇列，也 MUST NOT（不得）觸發自動下載。

#### Scenario: Auto download priority
- **WHEN** 偵測到通過該頻道關鍵字篩選的新影片
- **THEN** 新任務插入佇列頂部並自動觸發下載流程

#### Scenario: 未命中關鍵字的新影片不觸發優先下載
- **WHEN** 本輪偵測到符合既有新片條件的影片，但全部未命中該頻道的關鍵字篩選
- **THEN** 系統 MUST NOT（不得）建立任何下載任務、插入佇列或自動開始下載
- **AND** 系統 MUST 仍更新該頻道的檢查時間，並依錨點上限守門規則處理時間錨點

## ADDED Requirements

### Requirement: 頻道訂閱可選多關鍵字篩選

系統 MUST（必須）允許每個頻道訂閱保存零個或多個影片標題關鍵字。關鍵字設定 MUST 為選填；未設定有效關鍵字（含缺少該欄位、清單為空或全部為空白項目）時，該頻道的所有新影片 MUST 按既有全量追蹤規則處理。設定一個以上有效關鍵字時，系統 MUST 僅讓標題命中任一關鍵字的影片通過篩選（OR 語意，命中判定為標題子字串比對）。

系統 MUST（必須）在比對前對「每個關鍵字」與「影片標題」各自套用同一組正規化程序，依序為：一、相容性正規化，將全形英數與相容字元折算為半形標準形式；二、折算至同一中文字形域，將繁體與簡體字形一律轉換為同一字形域（本專案以既有的簡繁轉換能力把兩側皆轉為簡體）；三、轉為小寫。因入庫的影片標題可能已被既有的整串簡繁轉換規則改寫而字形不穩定，字形域折算 MUST（必須）同時套用於關鍵字與標題兩側，才能穩定命中。系統 MUST NOT（不得）只正規化其中一側。

關鍵字正規化時，「空白」的定義 MUST（必須）涵蓋所有 Unicode 空白字元，以及零寬字元（U+200B、U+200C、U+200D、U+2060、U+FEFF）；僅由這些字元組成的項目 MUST 視為空白項目並忽略，項目前後的這些字元 MUST 被去除。使用者輸入 MUST 以逗號（半形與全形）作為關鍵字之間的分隔符，因此單一關鍵字 MUST NOT（不得）包含逗號。去除重複項目 MUST 以正規化後的值判定，並 MUST 保留使用者輸入中第一個對應項目的原始文字（原始大小寫與原始字形）作為顯示文字。

#### Scenario: 未設定關鍵字維持既有行為
- **WHEN** 頻道訂閱未包含關鍵字欄位、關鍵字清單為空，或清單只包含空白項目
- **THEN** 系統將該頻道所有符合既有新片條件的影片視為可下載，不額外套用標題篩選

#### Scenario: 任一關鍵字命中影片標題
- **WHEN** 頻道設定多個有效關鍵字，且新影片標題包含其中任一關鍵字
- **THEN** 系統將該影片視為通過關鍵字篩選並依既有流程建立下載任務

#### Scenario: 關鍵字比對正規化
- **WHEN** 使用者儲存包含前後空白、重複項目或英文字母大小寫差異的關鍵字
- **THEN** 系統 MUST 去除前後空白、忽略空白項目、以正規化後的值去除重複項目，並以不分英文大小寫的標題子字串進行比對

#### Scenario: 簡繁字形不影響命中
- **WHEN** 使用者以繁體字形輸入關鍵字，而影片標題以簡體字形呈現同一詞（或兩者字形相反）
- **THEN** 系統 MUST 判定為命中，因為關鍵字與標題已被折算至同一中文字形域後才比對
- **AND** 同一關鍵字 MUST 對繁體與簡體兩種字形的標題得到一致的命中結果

#### Scenario: 全形與半形英數視為相同
- **WHEN** 關鍵字或影片標題中的英文字母、數字以全形字元書寫（例如全形英文與半形英文互異）
- **THEN** 系統 MUST 在相容性正規化後判定為相同字元並正常命中

#### Scenario: 僅含空白或零寬字元的關鍵字被忽略
- **WHEN** 使用者輸入的關鍵字項目只由空白字元或零寬字元（U+200B、U+200C、U+200D、U+2060、U+FEFF）組成
- **THEN** 系統 MUST 將該項目視為空白項目並排除於有效關鍵字之外
- **AND** 若所有項目皆被排除，該頻道 MUST 回到未設定關鍵字的全量追蹤行為

#### Scenario: 去重後保留第一個項目的顯示文字
- **WHEN** 使用者輸入的多個關鍵字在正規化後相同（例如大小寫或簡繁字形不同的同一詞）
- **THEN** 系統 MUST 只保留一個有效關鍵字
- **AND** 保留的顯示文字 MUST 為使用者輸入中第一個對應項目的原始文字，MUST NOT（不得）改寫為其他項目或正規化後的字形

#### Scenario: 所有關鍵字皆未命中
- **WHEN** 新影片標題未包含該頻道的任何有效關鍵字
- **THEN** 系統 MUST NOT（不得）為該影片建立下載任務或下載通知
- **AND** 系統 MUST NOT（不得）為該影片查詢直播或首播狀態（直播與首播的守門行為由自動檢查過濾能力規範）
- **AND** 系統 MUST NOT（不得）將該影片列為未處理影片，使其得以依錨點上限守門規則被錨點越過

#### Scenario: RSS 與備援來源使用相同篩選
- **WHEN** 頻道影片來自官方 RSS 或啟用後的 yt-dlp 備援來源
- **THEN** 系統 MUST 對兩種來源套用完全相同的關鍵字正規化與標題比對規則

#### Scenario: 關鍵字數量不增加外部擷取次數
- **WHEN** 一個頻道訂閱設定一個或多個關鍵字並執行檢查
- **THEN** 系統 MUST 每次只擷取一次該頻道的 RSS 或必要的單次備援結果，再於本機篩選影片
- **AND** 系統 MUST NOT（不得）為每個關鍵字分別提出外部擷取請求

#### Scenario: 修改或清空關鍵字
- **WHEN** 使用者新增、刪除或清空既有頻道的關鍵字
- **THEN** 系統 MUST 將新設定套用於之後發現的新影片
- **AND** 系統 MUST NOT（不得）因設定改變而回溯下載先前已檢查或已略過的影片
- **AND** 清空所有關鍵字後，該頻道 MUST 恢復既有的全量新片追蹤行為

#### Scenario: 手動與模擬檢查遵守關鍵字
- **WHEN** 使用者對單一頻道或全部頻道執行立即檢查或模擬新片測試
- **THEN** 系統 MUST 使用與自動排程完全相同的關鍵字規則選擇可建立任務的影片
- **AND** 若沒有影片命中，系統 MUST NOT（不得）建立任何測試任務（結果提示文案由頻道檢查結果回饋能力規範）
