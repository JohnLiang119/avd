## Purpose

定義下載任務樹的持久化與還原語意：應用程式非正常結束後如何處理中斷的任務、哪些欄位屬於瞬時狀態而不應落地、以及歷史任務的保留上限，使任務清單在跨次啟動之間保持正確且儲存成本有明確上界。

## ADDED Requirements

### Requirement: 中斷任務的還原清理

應用程式啟動還原任務樹時，對於仍處於 `downloading` 或 `pending` 狀態的任務，系統 MUST（必須）將其標記為 `error` 並提供可辨識的中斷原因，使使用者能重試。此清理結果 MUST（必須）成為還原後的最終狀態，不得被任何後續的還原步驟覆蓋。

#### Scenario: 應用程式於下載中被強制關閉

- **WHEN** 應用程式在有任務處於 `downloading` 狀態時被強制關閉，隨後重新啟動
- **THEN** 該任務狀態為 `error`，並顯示中斷原因訊息
- **AND** 該任務提供重試操作
- **AND** 此行為在 Windows 與 Android 上一致

#### Scenario: 巢狀群組中的中斷任務

- **WHEN** 被中斷的任務位於頻道群組下的播放清單子任務中
- **THEN** 該子任務與其所屬的頻道群組皆標記為 `error`

#### Scenario: 清理結果的持久性

- **WHEN** 完成中斷清理後，使用者未進行任何操作即再次關閉並啟動應用程式
- **THEN** 任務仍維持 `error` 狀態，不會回到 `downloading`

### Requirement: 瞬時狀態不納入任務樹的對外投影

`progress`、`eta`、`speed`、`line` 等下載期間的即時數值，以及 `expanded` 等單機檢視狀態，MUST NOT（不得）納入任務樹的持久化內容，亦 MUST NOT（不得）納入跨裝置傳輸的推送內容。任務樹在下載進行期間，其對外投影 MUST（必須）保持不變。

#### Scenario: 下載進行期間的持久化寫入

- **WHEN** 任一任務正在下載，持續產生進度更新
- **THEN** 系統不因進度數值變動而寫入持久化儲存
- **AND** 僅在任務狀態發生轉換時寫入一次

#### Scenario: 跨裝置推送任務清單

- **WHEN** 使用者將任務清單推送至另一台裝置
- **THEN** 推送內容不包含來源裝置的展開／收合狀態
- **AND** 接收端依自身的檢視狀態呈現

#### Scenario: 還原後的瞬時欄位

- **WHEN** 應用程式重新啟動並還原任務樹
- **THEN** 各任務的進度、速度、剩餘時間顯示為該任務當前狀態對應的預設值，不呈現關閉前殘留的過期數值

### Requirement: 歷史任務保留上限

系統 MUST（必須）對處於終態（`success` 或 `error`）的葉任務數量設定保留上限。超出上限時 MUST（必須）依建立順序由舊至新裁切，並在裁切後移除因此變空的播放清單與頻道群組。處於 `pending` 或 `downloading` 的任務 MUST NOT（不得）因保留上限而被裁切。

#### Scenario: 終態任務超出上限

- **WHEN** 終態葉任務數量超過保留上限
- **THEN** 系統移除最舊的終態任務直到符合上限
- **AND** 並向使用者說明已自動清理的筆數

#### Scenario: 裁切後產生空群組

- **WHEN** 裁切導致某個播放清單或頻道群組底下已無任何子任務
- **THEN** 系統一併移除該空群組

#### Scenario: 活躍任務不受裁切

- **WHEN** 任務樹中同時存在超出上限的終態任務與若干 `pending` 任務
- **THEN** 所有 `pending` 任務皆被保留，僅終態任務被裁切
