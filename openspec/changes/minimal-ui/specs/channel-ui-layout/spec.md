## REMOVED Requirements

### Requirement: Two-line Card Structure

**Reason**: 該需求明訂卡片 MUST 維持雙行且 MUST NOT 擴增為第三行。實際使用顯示第二行已過載 —— 最新影片標題、關鍵字篩選入口與測試按鈕擠在同一行，使標題被截斷到只剩數個字而失去參考價值。極簡化的目標是讓重要資訊看得見，維持行數上限反而與之衝突，故改以逐項獨占一行的結構重新規範。

**Migration**: 由下方 ADDED 的「Four-line Card Structure」取代。原需求中與行數無關的約束**全部保留**且未放寬：關鍵字篩選入口仍 MUST 顯示「全部影片」或生效關鍵字數量、數量仍 MUST 為正規化後的項數、過長標題仍 MUST 截斷且 MUST NOT 造成橫向捲軸、點擊入口仍 MUST 只開啟編輯介面而不觸發其他動作、不同建立來源仍 MUST 顯示一致。

## ADDED Requirements

### Requirement: Four-line Card Structure

系統 MUST（必須）在頻道卡片中採用四行佈局：第一行展示頭像、頻道名稱、啟用開關與取消追蹤按鈕；第二行展示最新影片的發布時間；第三行展示最新影片的標題；第四行展示關鍵字篩選入口與測試按鈕。

**發布時間與影片標題 MUST（必須）各自獨占一行。** 兩者併於同一行時，時間佔去約二十個字元的固定寬度，使標題在手機寬度下僅餘數字可見 —— 而標題才是使用者判斷「這支要不要看」的依據，時間只是輔助。實測顯示併行的版面會把標題截斷至六至八個字。

**頭像 MUST（必須）為該頻道的真實頻道圖像**，MUST NOT（不得）以平台通用標誌（例如 YouTube 網站圖示）替代。取不到頻道圖像時 MUST（必須）呈現不帶品牌意涵的中性佔位，使「尚未取得」與「這就是該頻道的樣子」可被分辨。

關鍵字篩選入口 MUST（必須）以精簡形式顯示該頻道目前的篩選狀態：未設定有效關鍵字時 MUST 顯示「全部影片」，已設定時 MUST 顯示實際生效的關鍵字數量。

卡片 MUST NOT（不得）擴增為第五行。過長的頻道名稱或影片標題 MUST（必須）以截斷方式收斂於所屬行內，MUST NOT（不得）造成橫向捲軸。

卡片 MUST NOT（不得）使用巢狀的容器（框中框）分隔其各行 —— 分組 MUST（必須）以留白與至多一條分隔線達成。

#### Scenario: Display four-line layout

- **WHEN** 使用者開啟頻道追蹤清單
- **THEN** 卡片正確分為四行顯示對應的資訊與操作
- **AND** 最新影片標題 MUST 獨占一行，其可用寬度 MUST NOT 因發布時間而被佔去

#### Scenario: 影片標題較長

- **WHEN** 某頻道的最新影片標題在手機寬度下超過單行可容納的長度
- **THEN** 該標題 MUST 使用該行的完整寬度後才截斷
- **AND** 發布時間 MUST NOT 與其共用同一行而壓縮其可用寬度

#### Scenario: 頭像為真實頻道圖像

- **WHEN** 某頻道已成功取得其頻道圖像
- **THEN** 卡片第一行 MUST 顯示該頻道的圖像
- **AND** 系統 MUST NOT 顯示 YouTube 網站圖示或其他平台通用標誌

#### Scenario: 尚未取得頻道圖像

- **WHEN** 某頻道的頻道圖像尚未取得或取得失敗
- **THEN** 系統 MUST 呈現不帶品牌意涵的中性佔位
- **AND** 使用者 MUST 能分辨該狀態與「已取得圖像」不同

#### Scenario: 未設定關鍵字的入口狀態

- **WHEN** 某頻道訂閱未設定關鍵字、關鍵字清單為空，或清單內容經正規化後不存在有效項目
- **THEN** 該頻道第四行的關鍵字篩選入口 MUST 顯示「全部影片」，明確表示目前不套用標題篩選

#### Scenario: 已設定關鍵字的入口顯示生效數量

- **WHEN** 某頻道訂閱設有一個以上有效關鍵字
- **THEN** 該頻道第四行的關鍵字篩選入口 MUST 顯示實際生效的關鍵字數量
- **AND** 該數量 MUST 為去除空白項與重複項後的項數（例如使用者輸入三項但其中兩項正規化後互為重複時 MUST 顯示 2），MUST NOT 顯示使用者原始輸入的筆數

#### Scenario: 長內容不擴增卡片行數

- **WHEN** 頻道名稱、最新影片標題較長或關鍵字數量較多，且在手機寬度下顯示卡片
- **THEN** 卡片 MUST 仍為四行，MUST NOT 出現第五行或使關鍵字篩選入口、測試按鈕被推擠到不可點擊
- **AND** 過長的內容 MUST 以截斷方式收斂於所屬行內，MUST NOT 造成橫向捲軸

#### Scenario: 點擊關鍵字入口只開啟編輯介面

- **WHEN** 使用者點擊某頻道第四行的關鍵字篩選入口
- **THEN** 系統 MUST 開啟該頻道專屬的關鍵字編輯介面
- **AND** 系統 MUST NOT 因此變更該頻道的啟用狀態、刪除該頻道，或發起任何下載或測試任務

#### Scenario: 不同建立來源的入口顯示一致

- **WHEN** 頻道是由頻道管理彈窗新增、由網址列自動加入追蹤，或由備份還原匯入
- **THEN** 該頻道第四行的關鍵字篩選入口 MUST 依同一組關鍵字正規化規則計算並顯示狀態與數量
- **AND** 相同的關鍵字輸入內容 MUST NOT 因建立來源不同而顯示不同的狀態或數量

### Requirement: 取消追蹤按鈕維持既有的視覺辨識度

取消追蹤按鈕 MUST（必須）維持明確的視覺邊界與足夠的視覺尺寸，**不適用**其他操作按鈕的視覺收斂。

此例外有其理由：該按鈕與啟用開關緊鄰，且其操作沒有二次確認。移除頻道雖可重新加入，但該頻道已設定的關鍵字會永久遺失 —— 縮小其視覺目標會提高誤觸機率，而誤觸的代價無法復原。

#### Scenario: 取消追蹤按鈕的外觀

- **WHEN** 使用者檢視頻道卡片
- **THEN** 取消追蹤按鈕 MUST 具備明確的視覺邊界
- **AND** 其視覺尺寸 MUST NOT 因全應用程式的視覺收斂而縮小

#### Scenario: 與啟用開關的區辨

- **WHEN** 取消追蹤按鈕與啟用開關相鄰顯示
- **THEN** 兩者 MUST 可被明確區分
- **AND** 兩者之間 MUST 保有足以避免誤觸的間距
