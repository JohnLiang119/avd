## ADDED Requirements

### Requirement: 以 API 取得並修復頻道頭像

系統 MUST（必須）以 YouTube Data API 取得頻道的頭像，供頻道清單顯示使用。

此需求源於既有取得方式的結構性缺陷：頻道識別碼與 `/channel/...` 形式的網址在解析時**不會產生任何頭像**，而其餘路徑倚賴網頁中繼資料，並不可靠。頭像先前只在加入頻道當下取得一次，之後永不更新，故一旦當時取不到就永久停留在通用標誌。

頭像的取得 MUST NOT（不得）額外消耗配額 —— 它與頻道名稱來自**同一個請求**，MUST（必須）於該請求中一併取得，MUST NOT（不得）為此另發請求。

**修復的觸發條件 MUST（必須）涵蓋「頭像缺失」**，而不僅是「名稱缺失」。既有的啟動修復只在頻道名稱看似識別碼時執行；名稱正常但頭像缺失的頻道因此永遠不會被修復，而那正是多數受影響頻道的實際狀態。

頭像取得失敗 MUST NOT（不得）阻擋任何操作：MUST NOT 阻擋頻道加入，也 MUST NOT 使該頻道的檢查失敗。

頭像來源網址失效時，系統 MUST（必須）使其能於後續修復中重新取得，MUST NOT（不得）以替換為通用標誌的方式掩蓋失效狀態 —— 那會使該頻道永久停留在錯誤的呈現且無從察覺。

#### Scenario: 加入頻道時取得頭像

- **WHEN** 使用者加入一個新頻道且金鑰有效
- **THEN** 系統 MUST 以 API 取得該頻道的頭像
- **AND** 該次取得 MUST 與頻道名稱共用同一個請求，MUST NOT 額外消耗配額

#### Scenario: 既有頻道的頭像缺失

- **WHEN** 某個已追蹤頻道的名稱正常但頭像缺失
- **THEN** 系統 MUST 於修復時機以 API 取得其頭像
- **AND** 系統 MUST NOT 因該頻道名稱正常就略過修復

#### Scenario: 頭像取得失敗不阻擋加入

- **WHEN** 頭像的 API 查詢失敗（配額耗盡、金鑰無效或網路錯誤）
- **THEN** 系統 MUST 仍將該頻道加入追蹤清單
- **AND** 該頻道 MUST 於後續修復成功時取得頭像

#### Scenario: 頭像網址失效

- **WHEN** 已儲存的頭像網址無法載入
- **THEN** 系統 MUST 使該頻道於後續修復中重新取得頭像
- **AND** 系統 MUST NOT 以平台通用標誌取代而使失效狀態無從察覺

#### Scenario: 未設定金鑰時不影響其他功能

- **WHEN** 使用者未設定 API 金鑰
- **THEN** 頭像 MUST NOT 被取得，且該頻道 MUST 依既有規則呈現中性佔位
- **AND** 影片下載、播放清單解析與頻道網址解析 MUST 照常運作
