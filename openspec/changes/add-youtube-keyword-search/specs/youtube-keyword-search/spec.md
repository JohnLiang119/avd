# Spec Delta

## Purpose

讓使用者在 App 內以關鍵字搜尋 YouTube 影片，將搜尋結果以明細勾選方式批次下載，而不必離開 App 到瀏覽器搜尋再逐一複製網址。

## ADDED Requirements

### Requirement: 非網址輸入須被視為搜尋關鍵字並先徵詢確認

使用者於主輸入框送出不以 `http://`／`https://` 開頭的非空白文字時，系統 MUST 徵詢「以此文字搜尋 YouTube」的確認；確認後 MUST 以該文字執行搜尋，取消則 MUST 不執行任何動作並保留輸入內容。系統 MUST NOT 在未經確認下逕行搜尋——打錯的網址（如漏掉協定前綴）才有機會被使用者發現並退回。

#### Scenario: 輸入關鍵字並確認搜尋

- **WHEN** 使用者輸入「周杰倫」並送出，且於確認對話框按下確認
- **THEN** 系統以「周杰倫」為關鍵字執行 YouTube 搜尋，並顯示搜尋中的可取消提示

#### Scenario: 取消搜尋確認

- **WHEN** 使用者送出非網址文字後，於確認對話框取消
- **THEN** 系統不執行搜尋、不報錯，輸入框內容保持原樣

#### Scenario: 空白輸入維持既有提示

- **WHEN** 使用者送出空字串或僅含空白的文字
- **THEN** 系統顯示既有的輸入提示，不觸發搜尋確認

### Requirement: 搜尋不得依賴 YouTube Data API

關鍵字搜尋 MUST NOT 消耗 YouTube Data API 配額，也 MUST NOT 要求使用者先設定 API 金鑰——配額保留給頻道自動追蹤使用。

#### Scenario: 未設定 API 金鑰時搜尋仍可用

- **WHEN** 使用者未設定任何 YouTube Data API 金鑰並執行關鍵字搜尋
- **THEN** 搜尋正常執行並回傳結果，不出現要求設定金鑰的訊息

### Requirement: 搜尋結果只列影片

搜尋結果明細 MUST 只包含單支影片；命中的頻道與播放清單 MUST 被濾除，且 MUST NOT 被展開為其內容影片——搜尋「某歌手」時第一筆常是其頻道，誤展開會把整個頻道的影片灌進明細。

#### Scenario: 搜尋結果含頻道命中

- **WHEN** 搜尋結果的第一筆為某頻道（而非影片）
- **THEN** 明細清單不含該頻道項目，也不含因展開該頻道而來的影片

### Requirement: 搜尋結果須進入既有的勾選明細與批次下載流程

搜尋成功且有結果時，系統 MUST 彈出與播放清單解析相同的批次下載嚮導對話框，列出各影片的標題與片長（有上限筆數，預設前 50 筆），沿用全選／全不選／單項勾選與整批加入下載佇列的既有行為；已在任務清單或已下載過的影片 MUST 先被濾除。搜尋無結果時 MUST 明確告知找不到相關影片。

#### Scenario: 搜尋成功後勾選批次下載

- **WHEN** 搜尋回傳多筆影片，使用者於嚮導對話框勾選其中數部並確認
- **THEN** 系統將勾選的影片整批加入下載佇列並開始下載

#### Scenario: 搜尋無結果

- **WHEN** 關鍵字搜尋回傳零筆影片
- **THEN** 系統顯示「找不到相關影片」之類的明確訊息，不彈出空白的勾選對話框

#### Scenario: 搜尋結果與既有任務去重

- **WHEN** 搜尋結果中部分影片已存在於任務清單
- **THEN** 這些影片不出現在勾選明細中；全部重複時以訊息告知，不彈出對話框

### Requirement: 搜尋不得記錄續抓進度

搜尋結果不是穩定序列，系統 MUST NOT 為搜尋記錄續抓進度；同一關鍵字再次搜尋 MUST 從頭執行新搜尋，MUST NOT 出現「繼續上次進度」的詢問，也 MUST NOT 以筆數範圍續抓。

#### Scenario: 同一關鍵字重複搜尋

- **WHEN** 使用者以同一關鍵字先後搜尋兩次
- **THEN** 兩次皆為完整的新搜尋，第二次不出現續抓詢問，結果筆數不受第一次影響

### Requirement: 搜尋批次下載的任務歸組與命名

自搜尋結果批次下載的任務，任務樹 MUST 歸組於「YouTube 搜尋 / <關鍵字>」之下；各影片完成下載後的顯示標題與檔名前綴 MUST 採用該影片實際所屬的頻道名稱，MUST NOT 以單一固定前綴套用全部——搜尋結果橫跨多個頻道。

#### Scenario: 搜尋下載的任務樹分組

- **WHEN** 使用者自「周杰倫」的搜尋結果勾選三部不同頻道的影片批次下載
- **THEN** 任務樹出現「YouTube 搜尋」群組，其下「周杰倫」清單含三個子任務

#### Scenario: 檔名前綴採影片實際頻道

- **WHEN** 搜尋下載的某影片屬於頻道「Jay Chou」
- **THEN** 該影片的顯示標題與檔名前綴為「Jay Chou」，而非「YouTube 搜尋」

### Requirement: 搜尋明細提供「只列中文」過濾開關

搜尋結果的勾選明細 MUST 提供「只列中文」過濾開關，預設關閉。開啟時明細 MUST 只顯示依文字啟發式判定為中文的影片——標題與頻道名含中日韓表意文字、且不含日文假名與韓文諺文；此判斷 MUST NOT 發出額外網路請求（搜尋結果沒有可靠的官方語言欄位，逐支補查會把幾秒的搜尋拖成幾分鐘）。開啟過濾後確認下載時，MUST 只包含**目前顯示且被勾選**的影片——被過濾隱藏的項目即使先前已勾選也不得被下載。此開關 MUST 只出現在搜尋來源的明細，一般播放清單／頻道解析不顯示。

#### Scenario: 開啟過濾後批次下載

- **WHEN** 搜尋明細含中文與非中文影片且全部已勾選，使用者開啟「只列中文」後確認下載
- **THEN** 只有判定為中文且顯示中的影片被加入下載佇列

#### Scenario: 啟發式判準

- **WHEN** 明細含標題「周杰倫 最好聽的歌」、「Jay Chou【晴天】Official MV」（頻道「周杰倫 Jay Chou」）、「TOKYO タワー巡り」、「BTS 방탄소년단 Dynamite」
- **THEN** 開啟過濾後前兩者顯示（含表意文字、無假名諺文），後兩者被濾除

#### Scenario: 過濾開關預設關閉且僅搜尋明細出現

- **WHEN** 使用者開啟搜尋結果明細，或開啟一般播放清單解析明細
- **THEN** 搜尋明細顯示預設關閉的「只列中文」開關；播放清單明細不顯示此開關

### Requirement: 兩平台行為一致

關鍵字搜尋於 Windows 桌面端與 Android 端 MUST 提供一致的行為：同樣的確認流程、結果過濾規則、勾選明細與批次下載。

#### Scenario: Android 端搜尋含頻道命中

- **WHEN** Android 端使用者搜尋的結果含頻道命中
- **THEN** 與桌面端相同，明細只列影片，頻道不被展開
