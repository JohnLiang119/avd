## ADDED Requirements

### Requirement: 偵測裝置網路層錯誤時提早停止本輪頻道檢查

系統在執行一輪頻道檢查（自動或手動觸發）時，若任一頻道的 RSS 擷取錯誤被分類為裝置網路層錯誤（如 DNS 解析失敗、連線逾時、連線被拒），MUST（必須）立即停止檢查本輪剩餘的已啟用頻道，不得逐一等待每個剩餘頻道各自跑完重試流程。

被提早停止而未檢查的頻道，本輪 MUST NOT（不得）更新其時間錨點（`lastPublishedTime`）或最近檢查時間，效果等同於本輪未執行到該頻道。

伺服器層錯誤（如 HTTP 404、500 等狀態碼回應）與內容層錯誤（如 RSS 內容解析失敗）MUST NOT（不得）觸發提早停止，僅裝置網路層錯誤觸發。

#### Scenario: 檢查途中偵測到裝置網路層錯誤

- **WHEN** 本輪頻道檢查進行中，某一頻道的 RSS 擷取錯誤被分類為裝置網路層錯誤
- **THEN** 系統立即結束本輪迴圈，不再檢查清單中尚未輪到的其餘已啟用頻道
- **AND** 已提早跳過的頻道，其時間錨點與最近檢查時間維持本輪執行前的既有數值不變

#### Scenario: 提早停止時的總結提示與日誌

- **WHEN** 本輪因裝置網路層錯誤而提早停止
- **THEN** 系統在總結提示與錯誤日誌中明確標註「本輪已提早結束，尚有 N 個頻道未檢查」，不得使用與「已檢查但失敗」相同的措辭
- **AND** N 為本輪清單中尚未被檢查到的已啟用頻道數量

#### Scenario: 伺服器層或內容層錯誤不觸發提早停止

- **WHEN** 本輪頻道檢查進行中，某一頻道的錯誤被分類為伺服器層或內容層錯誤，且尚未出現任何裝置網路層錯誤
- **THEN** 系統依現行邏輯記錄該頻道失敗並繼續檢查清單中的下一個已啟用頻道，不提早停止
