## Purpose

規範播放清單與頻道網址「解析階段」本身的行為界限：等待時間上限、單次抓取數量上限與分批續抓、使用者可中止性、跨平台一致性，以及在啟動高成本解析前的事前確認，使解析不會演變為長時間無法操作的介面凍結。

## ADDED Requirements

### Requirement: 解析階段須有時間上限

系統對播放清單／頻道網址的解析 MUST（必須）設有明確的時間上限。逾時後系統 MUST 結束等待、關閉載入提示、恢復介面可操作，並以失敗告知使用者。系統 MUST NOT（不得）讓解析等待無限延長。

#### Scenario: 解析超過時間上限

- **WHEN** 使用者輸入一個播放清單或頻道網址，而解析在時間上限內未能完成
- **THEN** 系統關閉載入提示、恢復介面可操作，並顯示解析失敗訊息，且不建立任何下載任務

#### Scenario: 解析在時間上限內完成

- **WHEN** 解析在時間上限內成功回傳項目
- **THEN** 系統照常顯示批次下載嚮導對話框，時間上限機制不影響正常流程

### Requirement: 解析階段須可由使用者中止

解析進行期間，系統 MUST 提供明確的取消途徑。使用者取消後，系統 MUST 立即恢復介面可操作，並 MUST 終止對應的背景解析行程，不得留下持續佔用網路或運算資源的孤兒行程。

#### Scenario: 使用者於解析期間取消

- **WHEN** 使用者在解析進行中選擇取消
- **THEN** 系統立即關閉載入提示、恢復介面可操作，並終止背景解析行程

#### Scenario: 取消後立即輸入另一網址

- **WHEN** 使用者取消一次解析後，隨即輸入另一個網址並送出
- **THEN** 新的解析正常啟動，且不受前一次已取消的解析干擾

### Requirement: 解析階段的重試須與下載階段分離

解析階段 MUST 採用最小化的自動重試，使暫時性或永久性的來源故障能迅速回報。下載階段既有的重試與「確定性錯誤不重試」策略 MUST NOT 因此受到影響。

#### Scenario: 來源解析器故障

- **WHEN** 解析所依賴的來源解析器對該網址無法運作
- **THEN** 系統在數十秒內回報失敗，而非因反覆自動重試而延長至數分鐘

#### Scenario: 下載階段的重試不受影響

- **WHEN** 一則下載任務因暫時性網路問題失敗
- **THEN** 系統仍依既有策略自動重試，其行為與本變更前相同

### Requirement: 解析行為須跨平台一致

Windows 與 Android 兩端對同一網址的解析 MUST 套用相同的時間上限、取消能力與重試策略。使用者 MUST NOT 因平台不同而在同一失敗情境下遭遇顯著不同的等待時間。

#### Scenario: 同一個會失敗的網址在兩個平台

- **WHEN** 使用者在 Windows 與 Android 分別輸入同一個必然解析失敗的網址
- **THEN** 兩端皆於各自的時間上限內回報失敗，且皆可在等待期間被取消

### Requirement: 高成本的使用者頁解析須先徵詢確認

對於指向創作者全部作品的使用者頁網址（YouTube 頻道、TikTok 使用者頁、Douyin 使用者頁），系統 MUST 在啟動解析前徵詢使用者確認，並告知該操作可能耗時。使用者拒絕時，系統 MUST NOT 啟動解析。

#### Scenario: 使用者確認掃描 TikTok 使用者頁

- **WHEN** 使用者輸入 TikTok 使用者頁網址並於確認對話框選擇繼續
- **THEN** 系統啟動解析，並套用時間上限與取消機制

#### Scenario: 使用者拒絕掃描

- **WHEN** 使用者輸入使用者頁網址並於確認對話框選擇略過
- **THEN** 系統不啟動解析，亦不顯示載入提示，直接返回輸入狀態

### Requirement: 單次解析須有數量上限

單次解析所抓取的項目數 MUST 有明確上限。系統 MUST NOT 因來源包含大量作品而一次抓取全部內容。

#### Scenario: 來源作品數超過上限

- **WHEN** 使用者解析一個作品數遠超過上限的創作者頁面
- **THEN** 系統只抓取上限數量的項目，並在可接受的時間內完成，而非枚舉全部內容

#### Scenario: 來源作品數少於上限

- **WHEN** 使用者解析一個作品數少於上限的播放清單
- **THEN** 系統抓取其全部項目，行為與本變更前相同

### Requirement: 超過上限的部分須可分批續抓

超過單次上限的內容 MUST NOT 被永久丟棄。系統 MUST 記住各來源已抓取到的位置；使用者再次解析同一來源時，系統 MUST 接續抓取下一批，並 MUST 提供「從頭開始」以重置該來源的進度。

進度 MUST 以與來源穩定對應的識別保存，不得因分享網址上易變的追蹤參數而被視為不同來源。續抓失敗時，系統 MUST NOT 推進進度。

#### Scenario: 接續抓取下一批

- **WHEN** 使用者對先前已抓取過前一批的來源再次送出同一網址並確認繼續
- **THEN** 系統抓取下一批項目，且事前確認對話框明確告知本次抓取的範圍

#### Scenario: 帶有不同追蹤參數的同一來源

- **WHEN** 使用者第二次分享同一個創作者頁面，網址帶有與上次不同的追蹤參數
- **THEN** 系統仍辨識為同一來源並接續進度，而非從頭重抓

#### Scenario: 從頭開始

- **WHEN** 使用者對已有進度的來源選擇「從頭開始」
- **THEN** 系統重置該來源的進度並自第一批重新抓取

#### Scenario: 續抓失敗

- **WHEN** 續抓因來源限流或網路問題而失敗
- **THEN** 系統回報失敗且不推進進度，使用者再次送出同一網址時仍抓取同一批

#### Scenario: 已抓到來源結尾

- **WHEN** 某次續抓回傳的項目數少於單次上限
- **THEN** 系統視為已抵達該來源結尾，並在下次解析時告知使用者已無更多內容可抓

### Requirement: 解析產出的項目網址須為可下載形式

解析所產出的每一個項目網址 MUST 為該平台可直接用於下載的正式網址形式。系統 MUST NOT 產出會落入通用解析器或導向錯誤頁的簡化網址。

#### Scenario: TikTok 項目網址

- **WHEN** 系統解析 TikTok 使用者頁並產出項目清單
- **THEN** 每個項目的網址皆包含創作者識別區段，能被 TikTok 專屬解析器接受，而非導向 404 頁面

#### Scenario: Douyin 項目網址

- **WHEN** 系統解析 Douyin 使用者頁並產出項目清單
- **THEN** 每個項目的網址皆為該平台可直接下載的正式形式
