## ADDED Requirements

### Requirement: 檢查進行中須有逐頻道進度回饋

頻道檢查進行期間，系統 MUST（必須）持續呈現進度，使使用者能分辨「仍在進行」與「已經卡住」。僅在開始時顯示一次提示、之後直到整輪結束才有下一則訊息 MUST NOT（不得）視為滿足此要求。

進度 MUST（必須）同時包含**已完成數與總數**，以及**當前正在檢查的頻道名稱**。頻道名稱是此要求的重點而非裝飾：追蹤只剩單一通道且逐頻道循序進行，一個緩慢或無回應的頻道會拖住整輪，而使用者與開發者在此之前都無從指認是哪一個。

進度回饋 MUST NOT（不得）包含 API 金鑰的任何片段。

檢查結束時，進度呈現 MUST（必須）讓位給既有的結果回饋，MUST NOT（不得）殘留於畫面上使使用者誤以為仍在進行。

#### Scenario: 檢查進行中

- **WHEN** 使用者觸發頻道檢查且該輪涵蓋多個頻道
- **THEN** 系統 MUST 於檢查期間持續呈現已完成數、總數與當前頻道名稱
- **AND** 每完成一個頻道，已完成數 MUST 隨之更新

#### Scenario: 某個頻道異常緩慢

- **WHEN** 某個頻道的擷取遲遲未完成
- **THEN** 進度呈現 MUST 停留在該頻道並持續顯示其名稱
- **AND** 使用者 MUST 能據此指認是哪一個頻道造成等待

#### Scenario: 檢查結束

- **WHEN** 該輪檢查結束，不論成功、部分失敗或中途停擺
- **THEN** 進度呈現 MUST 結束
- **AND** 系統 MUST 依既有規則呈現該輪的結果回饋

#### Scenario: 進度回饋不外洩金鑰

- **WHEN** 進度呈現於任何階段
- **THEN** 其內容 MUST NOT 包含 API 金鑰的任何片段
