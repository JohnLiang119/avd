## REMOVED Requirements

### Requirement: API 金鑰為選填設定且未設定時行為不變

**Reason**: 官方 RSS 與 yt-dlp 備援兩條通道已移除（見 `yt-dlp-rss-fallback` 的 REMOVED 說明），不再存在「未設定金鑰時的既有行為」可供維持。金鑰因此由選填提升為頻道追蹤的必要條件。

**Migration**: 由下方 ADDED 的「API 金鑰為頻道追蹤的必要條件」取代。既有的「不得內建開發者金鑰」與「金鑰須持久化」等約束於新需求中完整保留；金鑰的機密保護要求（`API 金鑰為機密，不得出現於任何可外流的輸出`）不受影響，維持原狀。

## ADDED Requirements

### Requirement: API 金鑰為頻道追蹤的必要條件

系統 MUST（必須）在頻道監控設定中提供 YouTube Data API 金鑰的輸入欄位。**未設定有效金鑰時，頻道追蹤 MUST（必須）停止運作**，且 MUST（必須）明確告知使用者原因與解法，MUST NOT（不得）靜默失效或改用其他資料來源。

金鑰 MUST（必須）與其他設定項一同持久化，並在應用程式重啟後正確還原。系統 MUST NOT（不得）內建、預載或以任何形式散布開發者自有的金鑰 —— 配額綁定 Google Cloud 專案而非使用者，內建單一金鑰會使所有使用者共用同一份每日配額，且該金鑰可自安裝檔取出。

未設定金鑰 MUST NOT（不得）影響頻道追蹤以外的功能：影片下載、播放清單解析、頻道網址解析等 MUST（必須）照常運作。

#### Scenario: 未設定金鑰時停止追蹤並告知

- **WHEN** 使用者未設定 API 金鑰，且自動或手動觸發頻道檢查
- **THEN** 系統 MUST NOT（不得）發出任何頻道影片擷取請求
- **AND** 系統 MUST（必須）明確告知頻道追蹤因缺少金鑰而停止，並指出可於設定中填入
- **AND** 系統 MUST NOT（不得）顯示為「目前沒有新影片」或任何暗示檢查已正常完成的訊息

#### Scenario: 未設定金鑰不影響其他功能

- **WHEN** 使用者未設定 API 金鑰，但貼上單一影片或播放清單網址進行下載
- **THEN** 該下載 MUST（必須）照常運作
- **AND** 頻道網址解析（將網址或 handle 轉為頻道識別碼）MUST（必須）照常運作

#### Scenario: 設定金鑰後重啟

- **WHEN** 使用者輸入有效金鑰並儲存，隨後重新啟動應用程式
- **THEN** 系統 MUST（必須）還原該金鑰並恢復頻道追蹤

#### Scenario: 金鑰僅含空白

- **WHEN** 使用者輸入的內容在去除前後空白後為空字串
- **THEN** 系統 MUST（必須）視為未設定金鑰，MUST NOT（不得）以空金鑰發出請求

### Requirement: 以 API 取得頻道名稱

系統 MUST（必須）以 YouTube Data API 取得頻道名稱，供加入頻道與既有頻道的名稱修復使用。

此需求源於移除 RSS：頻道名稱先前取自 RSS feed 根層的 `<title>`，該路徑已不存在。名稱取得失敗時，系統 MUST NOT（不得）阻擋頻道加入 —— MUST（必須）沿用既有的退回行為（以使用者輸入的網址作為暫時名稱），並於後續檢查時自動修復。

#### Scenario: 加入頻道時取得名稱

- **WHEN** 使用者加入一個新頻道且金鑰有效
- **THEN** 系統 MUST（必須）以 API 取得該頻道的名稱並顯示於頻道卡片

#### Scenario: 名稱取得失敗不阻擋加入

- **WHEN** 頻道名稱的 API 查詢失敗（配額耗盡、金鑰無效或網路錯誤）
- **THEN** 系統 MUST（必須）仍將該頻道加入追蹤清單
- **AND** 系統 MUST（必須）以使用者輸入的內容作為暫時名稱，並於後續檢查成功時自動修復

### Requirement: API 不可用時須有持續可見的狀態指示

當頻道追蹤因缺少金鑰、金鑰無效或配額耗盡而停止或降級時，系統 MUST（必須）在頻道管理介面提供**持續可見**的狀態指示，MUST NOT（不得）僅以一次性的提示訊息告知。

此需求的必要性來自備援移除：先前 API 失敗時仍有官方 RSS 與 yt-dlp 承接，追蹤不會中斷，一則飄過的提示尚可接受。移除備援後，API 不可用即等於**追蹤完全停止** —— 使用者若錯過那一則提示，可能數日後才發現完全沒有新片，而屆時已無從得知何時開始停止。

狀態指示 MUST（必須）能區分「未設定金鑰」、「金鑰無效」與「配額耗盡」三種原因，因為三者的解法不同（設定金鑰／修正金鑰／等待重置）。配額耗盡的指示 MUST（必須）說明其會自動恢復。狀態指示 MUST NOT（不得）包含金鑰的任何片段。

#### Scenario: 未設定金鑰時的持續指示

- **WHEN** 使用者未設定金鑰並開啟頻道管理介面
- **THEN** 系統 MUST（必須）顯示持續可見的指示，說明追蹤已停止且需設定金鑰

#### Scenario: 配額耗盡時的持續指示

- **WHEN** 配額已耗盡且抑制尚未解除
- **THEN** 系統 MUST（必須）顯示持續可見的指示，說明追蹤暫停與其自動恢復的時點
- **AND** 該指示 MUST（必須）與「金鑰無效」的指示可明確區分

#### Scenario: 金鑰無效時的持續指示

- **WHEN** 金鑰被 API 拒絕且抑制尚未解除
- **THEN** 系統 MUST（必須）顯示持續可見的指示，說明需修正金鑰
- **AND** 該指示 MUST NOT（不得）包含金鑰的任何片段

#### Scenario: 恢復正常後指示消失

- **WHEN** 金鑰已設定且有效、配額未耗盡
- **THEN** 系統 MUST NOT（不得）顯示上述任何停擺指示
