## Purpose

讓 AVD 使用者能在主畫面立即辨識裝置的網際網路可用性，並在離線或連線異常時取得清楚、可重新檢查且不干擾既有工作的狀態提示。

## ADDED Requirements

### Requirement: 主畫面呈現可辨識的網路狀態

系統 MUST 在非 TV 模式的主畫面「重整、清除、刪除、設定」與「音訊、頻道、快傳、收合」兩排控制按鈕最左側持續呈現目前網路狀態，並以文字清楚區分「檢查中」「正常」「不穩定」與「離線」；「不穩定」與「離線」MUST 同時併用圖示與文字，不得僅依賴顏色傳達狀態。

#### Scenario: 初次檢查網路
- **WHEN** 使用者開啟主畫面且系統尚未取得最新探測結果
- **THEN** 系統顯示「正在檢查連線」狀態（含小型轉圈動畫與文字），且主畫面其他操作仍可使用

#### Scenario: 網路正常
- **WHEN** 裝置具備網路連線且網際網路探測成功
- **THEN** 系統以精簡標籤顯示文字「網路正常」（不加色點或圖示），緊貼「重整」「音訊」兩排控制列最左側、與該兩排等高，控制按鈕仍靠右對齊，不占用完整警示列高度

#### Scenario: 裝置離線
- **WHEN** 裝置回報目前沒有可用網路連線
- **THEN** 系統於「重整」「音訊」兩排控制列正上方展開紅色全寬提示列，顯示「目前無法連上網際網路」及檢查 Wi-Fi 或行動網路的建議，並提供「重新檢查」操作

#### Scenario: 網路連線不穩定
- **WHEN** 裝置仍回報已連線，但網際網路探測失敗、逾時或取得非預期回應
- **THEN** 系統於「重整」「音訊」兩排控制列正上方以橘色全寬提示列顯示「網路不穩定」，並提供「重新檢查」操作，而不將狀態斷言為裝置完全離線

#### Scenario: TV 模式不顯示一般主畫面狀態
- **WHEN** AVD 處於 TV 接收模式
- **THEN** 系統不顯示一般主畫面的網路狀態元件，以維持 TV 接收畫面的既有資訊層級

### Requirement: 網路狀態可自動與手動更新

系統 MUST 在進入主畫面、裝置連線事件發生、應用回到前景及使用者要求重新檢查時更新狀態；主畫面保持可見期間 MUST 定期刷新，且較舊的探測結果不得覆蓋較新的狀態。

#### Scenario: 裝置發生離線事件
- **WHEN** 系統收到裝置離線事件
- **THEN** 主畫面立即切換為離線提示，不等待下一次定期探測

#### Scenario: 裝置恢復連線
- **WHEN** 系統收到裝置重新連線事件
- **THEN** 主畫面先顯示檢查中，並依最新探測結果切換為正常或不穩定

#### Scenario: 使用者手動重新檢查
- **WHEN** 使用者在離線或不穩定提示中選擇「重新檢查」
- **THEN** 系統立即啟動一次新的探測並顯示檢查中，完成後更新為最新結果

#### Scenario: 探測結果回傳順序顛倒
- **WHEN** 前一次探測晚於後一次探測完成
- **THEN** 系統只採用最後啟動之探測的結果，不讓過期結果回寫主畫面

### Requirement: 網路狀態僅供提示且與區域網路狀態分離

主畫面網路狀態 MUST 為資訊提示，不得因顯示離線或不穩定而停用、取消或略過既有下載、頻道檢查、背景排程及快傳操作。網際網路狀態 MUST 與既有快傳伺服器的區域網路狀態分開呈現。

#### Scenario: 離線時使用者仍可操作
- **WHEN** 主畫面顯示離線或不穩定
- **THEN** 系統不主動停用網址輸入、下載控制、頻道管理或快傳控制，實際操作結果仍由各功能既有錯誤處理決定

#### Scenario: Internet 不可用但區域網路仍可用
- **WHEN** 網際網路探測失敗但快傳伺服器仍在區域網路運作
- **THEN** 系統同時保留網際網路異常提示與快傳伺服器運行狀態，不將兩者合併或互相覆蓋
