## Purpose

以單一註冊表描述系統支援的每個媒體來源：如何從網址辨識它、它是單一影片還是多片集合、進度如何記錄、是否需要事前確認、其清單資料的完整度，以及哪些來源為已知不支援。

## ADDED Requirements

### Requirement: 來源判定須有單一真相

系統對「一個網址屬於哪個來源、該如何處理」的判定 MUST 集中於單一註冊表。網址樣式、進度鍵取法、集合與否、事前確認需求、清單資料完整度、項目網址組法，MUST 全部由該來源的同一筆宣告提供。

系統 MUST NOT 在流程各處各自以字串比對重新判斷來源。新增一個來源 MUST 只需在註冊表增加一筆。

#### Scenario: 新增一個來源

- **WHEN** 開發者為系統加入一個新的媒體來源
- **THEN** 只需在註冊表新增一筆宣告，流程各處無需個別修改即可正確辨識與處理該來源

#### Scenario: 未列於註冊表的網址

- **WHEN** 使用者輸入一個註冊表未涵蓋的網址
- **THEN** 系統視其為單一影片並照常處理，不因辨識失敗而中止

### Requirement: 集合來源須被辨識為多片而非單一影片

註冊表 MUST 標明每個來源是單一影片還是多片集合。被標為集合的網址 MUST 進入清單解析流程，MUST NOT 被當成單一影片直接推入下載佇列。

#### Scenario: 創作者頁面被正確辨識

- **WHEN** 使用者輸入一個指向創作者全部作品的網址
- **THEN** 系統進入清單解析流程並顯示勾選對話框，而非建立單一下載任務

#### Scenario: 集合被誤判為單一影片的後果不再發生

- **WHEN** 一個多片集合的網址被送入下載
- **THEN** 系統不會以單一影片的輸出樣板下載整個集合而使多支影片互相覆蓋

### Requirement: 已知不支援的來源須明確告知

註冊表 MUST 能標記「已知不支援」的來源。使用者輸入這類網址時，系統 MUST 給出明確說明該來源目前無法解析的訊息，MUST NOT 讓它進入註定失敗的解析流程而產生令人困惑的錯誤。

#### Scenario: 輸入已知不支援的來源

- **WHEN** 使用者輸入一個註冊表標記為不支援的來源網址
- **THEN** 系統立即顯示「此來源目前無法解析」的明確訊息，不啟動解析、不建立任務

### Requirement: 進度鍵須由來源宣告而非倚賴網址巧合

每個來源 MUST 宣告如何自其網址取出穩定的進度鍵。系統 MUST NOT 倚賴「易變參數剛好都位於查詢字串」這類巧合來達成穩定性。

#### Scenario: 帶有易變參數的集合網址

- **WHEN** 使用者兩次輸入同一個集合網址，兩次的追蹤參數不同
- **THEN** 系統依該來源宣告的規則取出相同的進度鍵，視為同一來源並接續進度

### Requirement: 會展開為多序列的來源須逐序列記錄進度

註冊表 MUST 標明一個來源是否會展開為多個獨立序列（例如頻道底下各自成串的分頁）。對這類來源，系統 MUST 為**每個序列各自記錄進度**，並以各序列自己的進度決定其下一批的抓取範圍。

系統 MUST NOT 以跨序列的合計筆數推算單一序列的抓取範圍 —— 該推算會使較長的序列在合計值超過其長度後再也取不到內容。

單次抓取上限對這類來源 MUST 理解為「每序列的上限」。

#### Scenario: 序列長度不一的來源續抓

- **WHEN** 使用者對一個含多個長度不一序列的來源連續抓取兩批
- **THEN** 每個序列各自自其上次的位置接續，較長的序列仍能取得其剩餘內容

#### Scenario: 部分序列已抓完

- **WHEN** 某來源的部分序列已抓到結尾、其餘尚未
- **THEN** 系統只對尚未抓完的序列繼續抓取，並僅在**所有**序列皆抓完時才將該來源標記為已抓完

#### Scenario: 事前確認須反映各序列的進度

- **WHEN** 使用者對一個已有進度的多序列來源再次送出網址
- **THEN** 事前確認對話框說明本次將抓取的範圍，且該說明能反映各序列不同的進度狀態

### Requirement: 已隨清單回傳的內容不得重複抓取

若清單解析的回應中已內含子序列的項目，且其內容與逐序列抓取的結果相同，系統 MUST 直接採用該內容，MUST NOT 為同一批資料再次發出請求。

#### Scenario: 首批解析一個多序列來源

- **WHEN** 系統解析一個多序列來源的第一批，且回應已內含各序列裁切後的項目
- **THEN** 系統直接採用這些項目，不再為各序列個別發出請求

#### Scenario: 續抓需要指定序列範圍

- **WHEN** 系統為某序列抓取非第一批的內容
- **THEN** 系統對該序列單獨發出帶有其範圍的請求

### Requirement: 註冊表須宣告清單資料的完整度

每個來源 MUST 宣告其清單解析結果是否已包含可供使用者選片的資訊（標題、片長、發布時間）。此宣告 MUST 作為是否啟動補齊階段的依據。

#### Scenario: 清單資料完整的來源

- **WHEN** 系統解析一個宣告資料完整的來源
- **THEN** 勾選對話框直接顯示標題與片長，不啟動補齊階段

#### Scenario: 清單資料不完整的來源

- **WHEN** 系統解析一個宣告資料不完整的來源
- **THEN** 勾選對話框先以退化標籤顯示項目，並啟動補齊階段
