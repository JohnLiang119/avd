## ADDED Requirements

### Requirement: API 配額耗盡的降級須明確告知

當本輪檢查因 YouTube Data API 配額耗盡而降級至官方 RSS 或 yt-dlp 備援時，系統 MUST（必須）在該輪的檢查結果回饋中明確告知已降級，並說明該狀態會在配額重置後自動恢復。

此告知 MUST NOT（不得）被「目前沒有新影片」或既有的連線失敗文案覆蓋 —— 降級後的候選視窗與發布時間精確度均下降（備援僅 2 筆且無精確時間），使用者需知道本輪的抓取品質與平常不同，才不會誤判漏片原因。

配額耗盡的告知 MUST（必須）與抓取失敗的告知在文字上可明確區分：前者代表「已改用其他通道、仍有取得資料」，後者代表「完全沒取到資料」。

#### Scenario: 配額耗盡但降級後成功取得新片

- **WHEN** API 配額耗盡，系統降級至官方 RSS 並成功建立 N 個下載任務
- **THEN** 系統 MUST 顯示發現 N 部新影片的訊息
- **AND** 該訊息 MUST 同時告知本輪已因配額耗盡而降級

#### Scenario: 配額耗盡且降級後無新片

- **WHEN** API 配額耗盡，降級後的通道成功抓取但本輪確實沒有新影片
- **THEN** 系統 MUST 告知已降級
- **AND** 系統 MUST NOT 僅顯示「目前沒有新影片」而不提降級

#### Scenario: 配額耗盡的告知不與抓取失敗混淆

- **WHEN** 本輪同時存在「因配額耗盡而降級」與「部分頻道抓取失敗」
- **THEN** 兩者 MUST 在同一則訊息中各自可辨識
- **AND** 系統 MUST NOT 以其中一者的文案取代另一者

### Requirement: API 金鑰無效須以可修正的方式告知

當 API 回報金鑰無效、已撤銷或未啟用該服務而導致降級時，系統 MUST（必須）顯示與配額耗盡**不同**的提示，並使使用者能辨認出這需要修正金鑰設定，而非等待配額重置。

系統 MUST NOT（不得）僅靜默降級 —— 使用者會誤以為 API 通道正在生效，而實際上每輪都在走較差的通道。此提示 MUST NOT（不得）包含金鑰的任何片段。

#### Scenario: 金鑰無效時的提示

- **WHEN** 本輪檢查因金鑰無效而降級至官方 RSS
- **THEN** 系統 MUST 顯示可辨識為「金鑰設定有問題」的提示
- **AND** 該提示 MUST 與配額耗盡的提示在文字上不同
- **AND** 該提示 MUST NOT 包含金鑰的任何片段

#### Scenario: 金鑰無效不重複騷擾

- **WHEN** 金鑰無效的狀態持續，且後續輪次仍以降級通道檢查
- **THEN** 系統 MUST NOT 於每個頻道或每輪重複顯示相同的金鑰錯誤提示
