## Purpose

讓 Android 手機在使用者設定的時刻與星期自動喚醒並播放指定頻道的電台直播（預設提供中廣新聞網與中廣流行網），在設定的時長後自動停止；即使應用程式未開啟、螢幕關閉或裝置處於省電待機，時間到仍 MUST 響起，行為與系統鬧鐘同級。

## ADDED Requirements

### Requirement: 鬧鐘清單

系統 MUST（必須）讓使用者維護一份鬧鐘清單。每筆鬧鐘 MUST（必須）包含：觸發時刻（24 小時制「時:分」）、觸發的星期（一至七天的子集合）、頻道、播放時長（分鐘，範圍 1 至 180，預設 30）與啟用狀態。使用者 MUST（必須）能新增、刪除、逐筆啟用或停用，並個別修改上述每一個欄位。

清單 MUST（必須）**預設為空**；沒有任何鬧鐘時，系統 MUST NOT（不得）有任何觸發。新增鬧鐘時的預設值 MUST（必須）為 06:00、每天、第一個內建頻道、30 分鐘、啟用。

星期 MUST（必須）預設全選，且每筆鬧鐘 MUST（必須）至少保留一天 —— 系統 MUST NOT（不得）允許取消最後一天。

同一個時刻 MAY（可以）出現在多筆鬧鐘中（例如平日與週末播不同頻道）；系統 MUST NOT（不得）以「時間重複」為由拒絕新增。

系統 MUST（必須）拒絕不合法的時刻（超出 00:00–23:59、非數字）並以文字提示原因，MUST NOT（不得）靜默忽略。

#### Scenario: 升級後預設不會響

- **WHEN** 使用者自不含本功能的版本升級並啟動應用程式
- **THEN** 鬧鐘清單為空，隔日早上 MUST NOT 有任何播放發生

#### Scenario: 新增一筆鬧鐘

- **WHEN** 使用者新增鬧鐘並接受預設值
- **THEN** 清單新增一筆 06:00、每天、第一個內建頻道、30 分鐘、啟用的鬧鐘
- **AND** 系統立即登錄其下一次觸發

#### Scenario: 同一時刻兩筆不同頻道

- **WHEN** 清單中已有 06:00（一至五、中廣新聞網），使用者再新增 06:00（六、日、中廣流行網）
- **THEN** 兩筆並存，各自依其星期觸發

#### Scenario: 取消最後一天

- **WHEN** 某筆鬧鐘只剩星期一被選取，使用者嘗試取消星期一
- **THEN** 系統拒絕，該筆仍保留星期一

#### Scenario: 停用單筆鬧鐘

- **WHEN** 使用者將 06:00 那筆切為停用
- **THEN** 該筆的已登錄觸發被取消，其餘啟用的鬧鐘不受影響

### Requirement: 頻道

系統 MUST（必須）提供至少兩個內建頻道：中廣新聞網與中廣流行網。內建頻道的串流網址 MUST（必須）於每次觸發時向中廣官方的頻道資訊來源依頻道名稱取得，不得寫死為唯一來源。

頻道模型 MUST（必須）能容納「自訂頻道」：以使用者提供的 http 或 https 串流網址直接播放，不查詢官方來源。自訂網址不合法者 MUST（必須）被拒絕並提示。本次 MAY（可以）不提供新增自訂串流頻道的介面，但資料模型與播放路徑 MUST（必須）已支援之。

頻道模型 MUST（必須）另能容納「本地檔案頻道」：由使用者自裝置選取的一或多個音訊或影片檔案組成的**有序清單**，順序為選取時的順序。系統 MUST（必須）於選取時將每個檔案複製一份至應用程式的私有儲存空間，並以該副本播放；MUST NOT（不得）直接引用原始檔案。任一檔案無法複製時，系統 MUST（必須）放棄建立該頻道並提示原因，MUST NOT（不得）建立只含部分檔案的頻道。系統 MUST（必須）提供新增本地檔案頻道（含多選）、檢視其檔案清單、重新命名與移除的介面；移除頻道時 MUST（必須）一併刪除其副本。

頻道模型 MUST（必須）另能容納「股票報價頻道」：由使用者輸入的一或多個股票代號組成的有序清單，觸發時向富果（Fugle）行情 API 取得每支的最新報價，以中文語音念出。富果 API 金鑰 MUST（必須）為單一的全域設定、由原生端持有，所有股票報價頻道共用。系統 MUST（必須）提供新增股票報價頻道、加入與移除股票、設定金鑰、重新命名與移除頻道的介面；加入股票時系統 SHOULD（應）以目前金鑰查詢一次以取得名稱供使用者確認，查詢失敗時 MUST（必須）仍允許加入並以文字說明原因。股票清單為空的頻道 MAY（可以）存在。

每筆鬧鐘 MUST（必須）指向恰好一個頻道。頻道被移除時，指向它的鬧鐘 MUST（必須）改指向第一個內建頻道，MUST NOT（不得）因此失效或消失。

#### Scenario: 選擇頻道

- **WHEN** 使用者將某筆鬧鐘的頻道改為中廣流行網
- **THEN** 該筆下次觸發時播放中廣流行網的直播

#### Scenario: 自訂頻道

- **WHEN** 存在一個串流網址為 https://example.com/live.aac 的自訂頻道，且某筆鬧鐘指向它並觸發
- **THEN** 系統直接連向該網址，不向官方來源查詢

#### Scenario: 新增本地檔案頻道

- **WHEN** 使用者於頻道列選擇新增，並自選檔器一次選取 a.mp3、b.mp3、c.mp4
- **THEN** 三個檔案各複製一份至應用程式私有儲存空間
- **AND** 頻道列出現一個含三個檔案、順序為 a、b、c 的本地檔案頻道，可供鬧鐘指向

#### Scenario: 其中一個檔案無法複製

- **WHEN** 使用者選取三個檔案，其中一個因空間不足而無法複製
- **THEN** 系統不建立該頻道，並以文字提示無法複製的原因

#### Scenario: 移除本地檔案頻道

- **WHEN** 使用者移除一個被某筆鬧鐘指向的本地檔案頻道
- **THEN** 該頻道的所有副本被刪除
- **AND** 該筆鬧鐘改指向第一個內建頻道，未被刪除或停用

### Requirement: 時間到即喚醒並開始播放

對每一筆啟用的鬧鐘，系統 MUST（必須）在裝置本地時間到達該時刻、且當日星期屬於該筆所選的星期時開始播放，不論應用程式是否在前景、螢幕是否關閉、裝置是否處於省電待機。在網路正常的前提下，播放 MUST（必須）於該時刻起 60 秒內開始。

播放採**鬧鐘語意**：裝置處於靜音或勿擾模式時仍 MUST（必須）播放；音量跟隨系統的鬧鐘音量。

播放期間系統 MUST（必須）顯示一則持續性通知，內含頻道名稱、預計停止時間與「停止」操作；使用者選擇停止時，播放 MUST（必須）立即結束。播放 MUST（必須）在該筆的播放時長到達時自動停止。

每次觸發後，系統 MUST（必須）立即登錄該筆鬧鐘的下一次觸發：自次日起第一個屬於所選星期的日子。

#### Scenario: 螢幕關閉、應用程式未開啟時觸發

- **WHEN** 週一 06:00 到達，該筆鬧鐘含星期一，應用程式未在前景且螢幕已關閉超過一小時
- **THEN** 裝置於 60 秒內開始播放該筆指定頻道的直播
- **AND** 通知列出現含「停止」的持續性通知

#### Scenario: 當日不在所選星期

- **WHEN** 某筆鬧鐘為 06:00、僅一至五，而今天是星期六
- **THEN** 今天 06:00 不播放，下一次登錄為星期一 06:00

#### Scenario: 勿擾模式下觸發

- **WHEN** 裝置處於勿擾或靜音模式而 07:00 到達
- **THEN** 播放仍以系統鬧鐘音量開始

#### Scenario: 播放時長到達

- **WHEN** 06:00 那筆時長為 30 分鐘，播放進行至 06:30
- **THEN** 播放自動停止，持續性通知消失

#### Scenario: 使用者自通知停止

- **WHEN** 播放進行中，使用者點選通知上的「停止」
- **THEN** 播放立即結束，通知消失，該筆鬧鐘的下一次觸發仍維持登錄

#### Scenario: 兩筆鬧鐘的播放重疊

- **WHEN** 06:00 那筆（時長 90 分鐘）仍在播放時 07:00 那筆（時長 30 分鐘）觸發
- **THEN** 播放不中斷、不重新開始，預計停止時間更新為兩者中較晚者（07:30）
- **AND** 頻道維持第一筆的頻道，MUST NOT 中途切換

### Requirement: 音量的控制與說明

播放音量 MUST（必須）以裝置的系統鬧鐘音量為上限，系統 MUST NOT（不得）改變裝置的系統鬧鐘音量設定。

系統 MUST（必須）另提供一個應用程式內的音量比例（0% 至 100%，預設 100%），於上述上限之下縮放本功能的播放音量。此比例為單一的全域設定，對所有鬧鐘一致生效；於播放進行中變更時 MUST（必須）立即生效，不需重新開始播放。

鬧鐘播放進行中，裝置的音量鍵 MUST（必須）調整鬧鐘音量，不論應用程式是否在前景。

設定介面 MUST（必須）以**不超過一行**的文字說明鬧鐘走鬧鐘音量、手動直播走媒體音量；MUST NOT（不得）以多行段落解釋。

#### Scenario: 調整應用程式內的音量比例

- **WHEN** 使用者將音量比例調為 50%，其後鬧鐘觸發
- **THEN** 播放的輸出音量為系統鬧鐘音量的 50%
- **AND** 裝置的系統鬧鐘音量設定未被改變

#### Scenario: 播放進行中調整比例

- **WHEN** 播放進行中，使用者變更音量比例
- **THEN** 音量立即改變，播放不中斷、不重新開始

#### Scenario: 播放進行中按裝置的音量鍵

- **WHEN** 鬧鐘播放進行中，使用者按下裝置的音量鍵，且應用程式正開啟於前景
- **THEN** 調整的是鬧鐘音量，播放音量隨之改變

### Requirement: 直播來源的解析與退回

內建頻道觸發時，系統 MUST（必須）向中廣官方的頻道資訊來源依該頻道的名稱取得目前的串流網址，優先採用加密（https）連線的網址。取得成功後系統 MUST（必須）按頻道記住該網址作為日後的後備。

官方來源在 5 秒內未回應、回應無法解析或其中找不到該頻道時，系統 MUST（必須）依序退回：該頻道上次成功播放的網址、再退回該頻道的內建網址。退回 MUST NOT（不得）造成使用者可感知的失敗。

自訂頻道 MUST（必須）直接使用其網址，MUST NOT（不得）查詢官方來源。

串流連線失敗或中斷時系統 MUST（必須）自動重試；自預定開始時刻起累計 3 分鐘仍無法播放時，系統 MUST（必須）放棄本次播放並依「失敗回報」處理。

#### Scenario: 官方來源正常

- **WHEN** 中廣流行網的鬧鐘觸發，官方來源在 5 秒內回傳含「中廣流行網」的頻道資訊
- **THEN** 系統以其中的 https 串流網址播放，並將該網址記為中廣流行網的後備

#### Scenario: 官方來源逾時

- **WHEN** 觸發時官方來源 5 秒內未回應
- **THEN** 系統以該頻道上次成功的網址播放；若從未成功過，以該頻道的內建網址播放
- **AND** 使用者感受不到差異（60 秒內開始播放）

#### Scenario: 串流中途斷線

- **WHEN** 播放中串流連線中斷
- **THEN** 系統自動重連並繼續播放，不需使用者介入

### Requirement: 重開機與時間變更後維持排程

裝置重開機、系統時間被調整或時區變更後，系統 MUST（必須）依目前設定重新登錄所有啟用鬧鐘的下一次觸發，使用者 MUST NOT（不得）需要開啟應用程式。

若上述變更使某筆鬧鐘的當日時刻已經過去，系統 MUST（必須）將其登錄至下一個符合星期的日子，MUST NOT（不得）立即補播。

#### Scenario: 重開機

- **WHEN** 裝置於 23:00 重開機，清單中有啟用的 06:00 與 07:00
- **THEN** 使用者未開啟應用程式，次日 06:00 與 07:00 仍如常播放

#### Scenario: 時鐘往前調整越過觸發時刻

- **WHEN** 05:50 時使用者將系統時間改為 06:20
- **THEN** 06:00 那筆不會立即播放，而是登錄至下一個符合星期的日子

### Requirement: 鬧鐘設定以原生端為權威來源

鬧鐘清單、頻道、音量比例 MUST（必須）在應用程式前端未執行時仍可被讀取並據以觸發。前端每次開啟設定介面 MUST（必須）自權威來源讀取目前值，MUST NOT（不得）保有可獨立寫入的副本。設定的任何變更 MUST（必須）立即生效並重新登錄受影響的觸發，不需重新啟動應用程式。

#### Scenario: 變更時間後不重啟

- **WHEN** 使用者把 06:00 改為 06:10 並關閉設定介面
- **THEN** 原本 06:00 的登錄被取消，06:10 被登錄，應用程式未重新啟動

#### Scenario: 前端儲存被清除

- **WHEN** 應用程式前端的網頁儲存（如 localStorage）被清空，但應用程式未被解除安裝
- **THEN** 鬧鐘設定不受影響，次日仍如常觸發，重新開啟設定介面時顯示的仍是原設定

### Requirement: 舊版設定的遷移

自含「每日時間清單」舊格式的版本升級時，系統 MUST（必須）將每筆舊時間遷移為一筆鬧鐘：星期全選、頻道為第一個內建頻道、時長與啟用狀態沿用。舊格式若填有自訂串流網址，系統 MUST（必須）建立一個自訂頻道並使所有遷移的鬧鐘指向它 —— 舊格式的自訂網址對所有時間生效，遷移後行為 MUST（必須）相同。舊格式的總開關為關閉時，遷移後的每筆鬧鐘 MUST（必須）為停用。

遷移 MUST（必須）只發生一次，MUST NOT（不得）覆蓋使用者遷移後的修改。

#### Scenario: 自舊格式升級

- **WHEN** 舊格式含 06:00 與 07:00、總開關開啟、無自訂網址
- **THEN** 遷移後為兩筆鬧鐘，皆為每天、中廣新聞網、啟用，時長沿用

#### Scenario: 舊格式填有自訂網址

- **WHEN** 舊格式的自訂串流網址為 https://example.com/live.aac
- **THEN** 遷移後存在一個以該網址為來源的自訂頻道，且所有遷移的鬧鐘指向它

#### Scenario: 舊格式總開關關閉

- **WHEN** 舊格式的總開關為關閉
- **THEN** 遷移後的每筆鬧鐘皆為停用，隔日 MUST NOT 有任何播放

### Requirement: 播放失敗的回報

播放無法開始或中途放棄時，系統 MUST（必須）以一則通知說明失敗原因（文字），並保留該次失敗的摘要：發生時間、操作情境與**未經截斷**的錯誤訊息。使用者下次開啟應用程式時，該摘要 MUST（必須）被寫入既有的錯誤紀錄（依 error-journal 規格），寫入後 MUST NOT（不得）重複寫入。

上次播放**失敗**時，設定介面 MUST（必須）顯示其時間與原因摘要；成功或從未觸發時 MAY（可以）不顯示。

#### Scenario: 觸發時完全沒有網路

- **WHEN** 06:00 到達但裝置無任何網路連線，且 3 分鐘內未恢復
- **THEN** 系統停止嘗試並顯示說明原因的通知
- **AND** 使用者下次開啟應用程式時，錯誤紀錄中出現這筆記錄（含時間、情境、完整訊息）
- **AND** 設定介面顯示該次失敗的時間與原因

### Requirement: 權限、平台與可用性告知

使用者首次新增鬧鐘時，系統 MUST（必須）請求顯示通知的權限；若裝置要求使用者於系統設定中允許精確鬧鐘，系統 MUST（必須）提供前往該設定的入口並說明未允許的後果。任何必要權限缺失時，系統 MUST（必須）於設定介面以文字告知影響，MUST NOT（不得）靜默失效；權限齊全時 MUST NOT（不得）顯示任何權限相關文字。

此功能僅於 Android 提供；Windows 端 MUST NOT（不得）顯示此設定區段。

#### Scenario: 通知權限被拒

- **WHEN** 使用者拒絕通知權限後 06:00 觸發
- **THEN** 播放仍如常開始並於時長到達時停止
- **AND** 設定介面顯示「未允許通知」的說明與重新授權的入口

#### Scenario: 權限齊全

- **WHEN** 通知與精確鬧鐘權限皆已允許
- **THEN** 設定介面不顯示任何權限相關的文字

#### Scenario: Windows 端

- **WHEN** 使用者於 Windows 版開啟偏好設定
- **THEN** 介面中不出現鬧鐘區段

### Requirement: 設定介面的結構與安靜原則

本功能的設定內容 MUST（必須）可被完整檢視與操作；當內容高度超過裝置畫面時，使用者 MUST（必須）能捲動至其中的每一個控制項。

鬧鐘清單 MUST（必須）以**時間為第一層**：每筆鬧鐘一張卡片，收合時 MUST（必須）呈現時刻、啟用開關，以及足以判斷設定的摘要（星期與頻道）；展開後 MUST（必須）依序呈現星期（第二層）與頻道（第三層），以及時長與移除操作。

頻道 MUST（必須）另成一列，每個頻道附立即收聽的操作。

介面 MUST（必須）遵守**正常時安靜、異常才說話**：系統登錄狀態、上次播放結果、權限提示 MUST NOT（不得）在一切正常時顯示；試播、測試鬧鐘等驗證用操作 MUST（必須）收於一個預設收合的「進階」區段。除音量的一行說明外，介面 MUST NOT（不得）包含多行的解釋段落。

#### Scenario: 內容高於畫面

- **WHEN** 設定內容的高度超過裝置畫面
- **THEN** 使用者能捲動至最下方的控制項並操作它

#### Scenario: 收合狀態下的鬧鐘卡片

- **WHEN** 某筆鬧鐘為 06:00、一至五、中廣新聞網、啟用，且處於收合狀態
- **THEN** 卡片呈現 06:00、啟用開關，以及可判讀出「一至五」與「中廣新聞網」的摘要

#### Scenario: 展開後的三層

- **WHEN** 使用者展開某筆鬧鐘
- **THEN** 依序可見並可操作：星期選擇、頻道選擇、時長、移除

#### Scenario: 一切正常時

- **WHEN** 系統已收下所有啟用的鬧鐘、權限齊全、上次播放成功或從未觸發
- **THEN** 介面不顯示登錄狀態、權限提示或上次播放結果

### Requirement: 手動收聽直播

頻道列的每個頻道 MUST（必須）提供一個立即收聽的操作，使使用者不需等到鬧鐘時間即可收聽該頻道的直播；此操作 MUST NOT（不得）依賴任何鬧鐘的存在或啟用狀態。

手動收聽 MUST（必須）與鬧鐘共用同一套來源解析與退回順序。其音訊 MUST（必須）採**媒體**語意：裝置處於靜音或勿擾模式時 MUST NOT（不得）強行出聲。

手動收聽 MUST（必須）可由同一個操作位置停止；播放進行中該位置 MUST（必須）呈現為停止而非播放，其他頻道的操作 MUST（必須）維持為播放。其長度 MUST（必須）有上限，且通知 MUST（必須）載明預計停止時間。

播放進行中，介面 MUST（必須）能讓使用者分辨目前是手動直播或鬧鐘播放，以及是哪一個頻道。

#### Scenario: 沒有任何鬧鐘時仍可收聽

- **WHEN** 鬧鐘清單為空，使用者按下中廣流行網的收聽
- **THEN** 系統開始播放中廣流行網的直播

#### Scenario: 靜音或勿擾模式下手動收聽

- **WHEN** 裝置處於靜音或勿擾模式，使用者按下收聽
- **THEN** 系統 MUST NOT 強行出聲，其音量依裝置的媒體音量而定

#### Scenario: 同一個位置停止

- **WHEN** 中廣新聞網的手動直播進行中
- **THEN** 中廣新聞網的操作呈現為停止，中廣流行網的操作維持為播放
- **AND** 使用者按下停止即結束播放

#### Scenario: 忘記關閉

- **WHEN** 手動直播開始後使用者未再操作
- **THEN** 播放於上限時間到達時自動停止
- **AND** 通知在此之前即載明預計停止時間

### Requirement: 本地檔案頻道的播放

指向本地檔案頻道的鬧鐘觸發時，系統 MUST（必須）依清單順序自第一個檔案開始播放，一個檔案結束即接續下一個，清單播畢即自第一個重新開始，直到該筆鬧鐘的播放時長到達或使用者停止。順序 MUST（必須）固定為清單順序，MUST NOT（不得）隨機。手動收聽本地檔案頻道時 MUST（必須）採同樣的循環方式，以手動收聽的長度上限為止。

播放本地檔案 MUST NOT（不得）存取網路，也 MUST NOT（不得）查詢官方來源。影片檔案 MUST（必須）只解碼並輸出其音訊，MUST NOT（不得）解碼影像。

觸發時若清單中的檔案全部不存在或無法讀取，系統 MUST（必須）依「播放失敗的回報」處理，訊息載明頻道名稱與檔案不存在的事實；MUST NOT（不得）改播其他頻道。若僅部分檔案無法讀取，系統 MUST（必須）跳過該些檔案播放其餘，並於上次播放結果載明無法讀取的數量。

鬧鐘播放本地檔案時的音訊語意、音量控制、通知、自動停止與重疊處理 MUST（必須）與播放直播時完全相同。

#### Scenario: 清單短於播放時長

- **WHEN** 某本地檔案頻道含兩個各 4 分鐘的檔案，指向它的鬧鐘時長為 30 分鐘並觸發
- **THEN** 依序播放第一、第二個檔案後自第一個重新開始，如此循環至 30 分鐘到達時停止

#### Scenario: 影片檔案

- **WHEN** 清單中含一個 mp4 檔案且輪到它播放
- **THEN** 只輸出其音訊，不解碼影像

#### Scenario: 全部檔案不存在

- **WHEN** 應用程式的私有儲存空間被清除，指向本地檔案頻道的鬧鐘觸發
- **THEN** 系統不播放任何聲音，顯示說明失敗原因的通知，並保留該次失敗的摘要供寫入錯誤紀錄
- **AND** 系統 MUST NOT 改播中廣新聞網或其他頻道

#### Scenario: 部分檔案不存在

- **WHEN** 三個檔案中有一個無法讀取而鬧鐘觸發
- **THEN** 系統播放其餘兩個檔案並循環
- **AND** 上次播放結果載明有一個檔案無法讀取

#### Scenario: 靜音下的鬧鐘

- **WHEN** 裝置處於靜音模式，指向本地檔案頻道的鬧鐘觸發
- **THEN** 播放仍以系統鬧鐘音量開始，與播放直播時相同

### Requirement: 股票報價頻道的播放

指向股票報價頻道的鬧鐘觸發時，系統 MUST（必須）依清單順序向富果 API 取得每支股票的報價，組成要念的句子，以裝置的文字轉語音合成為音訊後播放，並循環至該筆鬧鐘的播放時長到達或使用者停止。口說稿 MUST（必須）極簡：每支股票一句「名稱 價格」；MUST NOT（不得）念頻道名稱、資料日期、漲跌金額或漲跌幅。句與句之間的停頓長度 MUST（必須）可由使用者逐頻道設定（0 至 10 秒，預設 1 秒）；循環回第一句時 MUST（必須）只有同樣長度的一次停頓，MUST NOT（不得）額外多停。播放起來即為「南亞 213。（停頓）台化 89。（停頓）南亞 213。…」。

部分股票取不到報價時，系統 MUST（必須）在該支原本的位置念「名稱 無法取得」，其餘照念。**全部**股票取不到（未設定金鑰、離線、金鑰無效等）時，系統 MUST（必須）仍播放語音說明原因，並將該次結果記為失敗（依「播放失敗的回報」保留摘要），MUST NOT（不得）改播其他頻道。清單為空時 MUST（必須）念出尚未加入任何股票。

裝置沒有中文文字轉語音能力時，系統 MUST（必須）依「播放失敗的回報」處理並說明原因。

股票報價頻道播放時的音訊語意、音量控制、通知、自動停止與重疊處理 MUST（必須）與其他頻道完全相同；手動收聽 MUST（必須）採同樣的流程。

#### Scenario: 兩支股票皆取得

- **WHEN** 頻道含南亞（213 元）與台化（89 元），金鑰有效，鬧鐘觸發
- **THEN** 系統念出「南亞 213」、停頓設定的秒數、「台化 89」、停頓同樣秒數，再回到「南亞 213」，如此循環至時長到達；不念頻道名、日期或漲跌

#### Scenario: 調整停頓

- **WHEN** 使用者把某股票報價頻道的停頓改為 3 秒
- **THEN** 該頻道下次播放時每句之間停頓 3 秒，循環回第一句前亦為 3 秒

#### Scenario: 其中一支代號錯誤

- **WHEN** 頻道含一支不存在的代號
- **THEN** 系統在該支的位置念「代號 無法取得」，其餘股票照念

#### Scenario: 尚未設定金鑰

- **WHEN** 富果 API 金鑰為空而鬧鐘觸發
- **THEN** 系統不發出任何 API 請求，念出尚未設定金鑰，並將該次記為失敗

#### Scenario: 離線

- **WHEN** 觸發時裝置無網路
- **THEN** 系統念出無法取得股價與連不上伺服器，並將該次記為失敗，MUST NOT 改播其他頻道

#### Scenario: 沒有中文語音

- **WHEN** 裝置未安裝中文文字轉語音語音包
- **THEN** 系統不播放、顯示說明原因的通知，並保留失敗摘要

### Requirement: 鬧鐘機制必須可被使用者自行驗證

使用者 MUST（必須）能在不等到設定的觸發時間、也不必更動自己的鬧鐘清單的前提下，驗證「應用程式未執行時鬧鐘依然會響」這件事。

系統 MUST（必須）提供一個測試觸發，它 MUST（必須）走與正式觸發**完全相同**的路徑（系統鬧鐘、喚醒、播放），而非直接啟動播放。此測試 MUST NOT（不得）依賴任何鬧鐘的存在，MUST NOT（不得）在使用者的鬧鐘清單留下任何項目，且 MUST（必須）可於響起前取消。

測試響起的事實 MUST（必須）被持久記錄，並於使用者下次開啟應用程式時呈現。

系統 MUST（必須）**向系統回讀**鬧鐘的登錄狀態。當存在啟用的鬧鐘但系統中不存在本程式的任何鬧鐘時，介面 MUST（必須）明確告知「時間到不會響」並指出可能的原因；登錄正常時 MUST NOT（不得）顯示登錄狀態。

#### Scenario: 不等到早上就驗證

- **WHEN** 使用者啟動測試觸發後將應用程式完全關閉
- **THEN** 系統於約定時刻喚醒應用程式並播放
- **AND** 使用者的鬧鐘清單未因此增加任何項目

#### Scenario: 回到應用程式看結果

- **WHEN** 測試響起後，使用者重新開啟應用程式
- **THEN** 介面呈現該次測試響起的時刻

#### Scenario: 系統中沒有本程式的鬧鐘

- **WHEN** 清單中有啟用的鬧鐘，但系統中不存在任何本程式的鬧鐘
- **THEN** 介面明確告知時間到不會響，並指出可能的原因

#### Scenario: 登錄正常

- **WHEN** 清單中每筆啟用的鬧鐘都已存在於系統中
- **THEN** 介面不顯示登錄狀態

#### Scenario: 取消測試

- **WHEN** 測試尚未響起，使用者選擇取消
- **THEN** 該測試觸發被取消，不會再響

### Requirement: 試播

「進階」區段 MUST（必須）提供「試播」：立即依與正式觸發完全相同的來源解析路徑播放第一個內建頻道，30 秒後自動停止，並即時顯示成功或失敗原因。試播 MUST（必須）可由使用者提前停止。

#### Scenario: 試播成功

- **WHEN** 使用者點選試播且來源可連線
- **THEN** 數秒內開始播放，30 秒後自動停止

#### Scenario: 試播失敗

- **WHEN** 使用者點選試播但來源無法連線
- **THEN** 介面顯示失敗原因的完整文字，並將該錯誤寫入錯誤紀錄
