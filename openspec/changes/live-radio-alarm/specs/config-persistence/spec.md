## MODIFIED Requirements

### Requirement: 單一真相來源的設定持久化

系統 MUST（必須）透過單一儲存介面讀寫所有設定值，該介面在各平台上 MUST（必須）僅有一個權威來源。系統 MUST NOT（不得）同時維護兩份可獨立寫入的設定副本，也不得讓還原結果取決於哪一份先被讀取。

**唯一的例外是「原生端為權威來源的設定」**：必須在應用程式前端（WebView）未執行時仍能被原生端讀取並據以行動的設定（例如需在裝置待機時響起的鬧鐘），其權威來源 MUST（必須）位於原生端。此類設定 MUST（必須）滿足：

- 前端 MUST NOT（不得）另存可獨立寫入的副本，每次需要時 MUST（必須）自原生端讀取；
- 每個平台上仍 MUST（必須）只有一個權威來源；
- 讀寫 MUST（必須）經由單一專屬介面，呼叫端 MUST NOT（不得）為了持久化而自行判斷執行平台；
- 哪些設定屬於此類 MUST（必須）於其所屬能力的規格中明確列出，MUST NOT（不得）僅因便利而歸入此類。

#### Scenario: 寫入設定後重新啟動

- **WHEN** 使用者變更任一設定項（例如 MP3 模式、Wi-Fi 資訊、刪除確認開關）後關閉並重新啟動應用程式
- **THEN** 系統還原出的設定值與關閉前一致
- **AND** 還原結果在 Windows 與 Android 上表現相同

#### Scenario: 啟動還原期間的寫入

- **WHEN** 應用程式啟動、設定尚在還原過程中，此時發生設定寫入
- **THEN** 該次寫入 MUST NOT（不得）被後續完成的還原流程覆蓋

#### Scenario: 儲存來源為空或損毀

- **WHEN** 儲存來源不存在、內容為空、或 JSON 解析失敗
- **THEN** 系統以各設定項的預設值啟動，不中斷應用程式初始化，並於主控台記錄錯誤

#### Scenario: 原生端為權威來源的設定

- **WHEN** 某設定需在前端未執行時被原生端讀取（例如鬧鐘時間清單）
- **THEN** 該設定的唯一權威來源位於原生端，前端每次開啟相關介面時自原生端讀取
- **AND** 清空前端的網頁儲存不影響該設定
- **AND** 該設定於其能力規格中被明確標示為原生端權威
