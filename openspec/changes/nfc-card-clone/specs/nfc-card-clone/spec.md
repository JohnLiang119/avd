## Purpose

讓 Android 使用者在明確啟動操作後，將自己有權複製的來源卡 UID 寫入相容的 gen2/CUID 實體卡。規範來源準備、目標檢查、寫入範圍、重新感應驗證及中止結果，避免把卡號寫入成功誤認為完整門禁功能已複製。

## ADDED Requirements

### Requirement: 平台與一般讀卡隔離

系統 MUST 只在 Android NFC 讀卡機提供複製入口；Windows 與非 Android 環境 MUST NOT 顯示入口。NFC 不可用時 MUST 說明原因並停止複製。未明確啟動複製時，系統 MUST 維持一般 UID 讀取、歷史與剪貼簿行為，MUST NOT 為準備複製而驗證金鑰或讀取扇區。

#### Scenario: 一般讀卡不觸發複製

- **WHEN** 使用者只開啟讀卡畫面並感應卡片
- **THEN** 系統照常顯示 UID、提供剪貼簿複製與更新歷史，不存取 block 0 或啟動寫入

#### Scenario: 非 Android 或 NFC 不可用

- **WHEN** 使用者在非 Android 環境，或 Android 裝置無 NFC／NFC 已關閉
- **THEN** 非 Android 不顯示複製入口；Android 說明 NFC 狀態且不得啟動複製

### Requirement: 來源資格與明確準備

系統 MUST 在使用者選擇複製後固定本次來源 UID，要求重新感應相同 UID 的來源卡，並確認其為 4-byte UID 與已支援的 MIFARE Classic 相容卡型。僅有 4-byte UID 或 NFC 能力 MUST NOT 被視為足夠的相容性證明。來源準備 MUST 僅讀取 block 0，不寫入來源卡。來源資料 MUST 只供本次操作使用，不因其他一般讀卡事件改變。

#### Scenario: 來源準備成功

- **WHEN** 使用者啟動複製並重新感應相同 UID 的相容來源卡
- **THEN** 系統固定其 UID 與可取得的複製資料，顯示可用模式並提示移開來源卡

#### Scenario: 來源不相符或不支援

- **WHEN** 重新感應的來源 UID 不符、長度不是 4 byte，或手機與卡片組合不支援所需技術／卡型
- **THEN** 系統說明原因並停止本次準備，不把該卡當成寫入目標

### Requirement: 複製內容與模式

系統 MUST 僅使用明確的兩種模式：來源完整 block 0 可讀且通過 UID、BCC 與卡型相容性檢查時複製完整內容；來源金鑰驗證失敗或無法讀取 block 0 時，允許使用者選擇「僅複製 UID」，保留目標原有非 UID／BCC 位元組，只更新 UID 與正確 BCC。系統 MUST NOT 以任意佔位資料重建其餘內容，MUST NOT 將來源資料毀損或不相容自動降級為可寫模式。

目標 block 0 MUST 在寫入前可讀並通過檢查。完整模式與目標不相容時 MUST 拒絕寫入，不得靜默切換模式。使用者開始等待目標前 MUST 看見模式、目標將被覆寫及 UID 複製不保證門禁可用的說明。

#### Scenario: 完整 block 0 模式

- **WHEN** 來源完整 block 0 有效且目標相容
- **THEN** 系統使用與來源完全相同的 16-byte 預期內容

#### Scenario: 僅 UID 模式

- **WHEN** 來源 block 0 因存取限制不可讀，使用者選擇僅 UID，且目標 block 0 有效
- **THEN** 預期內容只有 UID 與 BCC 與目標原值不同，其餘位元組保留，畫面標示僅複製 UID

#### Scenario: 無效或不足的資料

- **WHEN** block 0 長度不符、UID／BCC 不符、卡型不相容，或無法讀取目標 block 0
- **THEN** 系統不寫入，明確說明無法準備有效資料

### Requirement: 目標資格與單次寫入

目標 MUST 是 4-byte UID、已驗證可透過標準寫入方式改寫 block 0 的 gen2/CUID 相容卡型，且本次能以預設金鑰存取 sector 0。系統 MUST NOT 僅依商品名稱、UID、探索資訊或金鑰驗證成功宣稱已辨識魔術卡世代；寫入被拒時回報可證實的失敗原因。

每次使用者啟動的操作 MUST 至多發出一次 block 0 寫入，所有必要檢查 MUST 在該次寫入前完成。系統 MUST NOT 寫入其他區塊、金鑰或存取條件。來源與目標 UID 相同時 MUST NOT 寫入，MUST 提示更換目標或改為唯讀核對。重新寫入 MUST 由使用者重新啟動。

#### Scenario: 相容目標

- **WHEN** 使用者將相容且 UID 不同的目標靠近，所有檢查均通過
- **THEN** 系統只寫入一次 block 0，接著進入驗證，不再接受其他寫入目標

#### Scenario: 來源仍貼近或目標已有相同 UID

- **WHEN** 等待目標時發現與來源相同的 UID
- **THEN** 系統不寫入並結束本次寫入待命，提示更換目標或進行唯讀核對

#### Scenario: 目標不支援

- **WHEN** 目標 UID 不是 4 byte、技術／卡型不支援、驗證失敗或存取被拒
- **THEN** 系統回報對應原因，不自動重試，不假稱已判定為 gen1a 或普通卡

#### Scenario: 重複回報同一張卡

- **WHEN** 同一次操作收到重複或並行的感應事件
- **THEN** 系統仍至多發出一次寫入，後續感應只能依目前狀態處理

### Requirement: 寫後驗證與結果語意

寫入後系統 MUST 先嘗試讀回完整 block 0 與預期內容逐位元組比較，再提示使用者移開並重新感應同一張目標卡。系統 MUST 使用重新感應取得的 UID 與完整 block 0 核對，MUST NOT 使用寫入前的 UID 快照作為新 UID 已生效的證據。

系統 MUST 只有在重新感應的 UID 及完整 block 0 皆相符時顯示「UID 複製完成」。若同次連線讀回中斷，後續重新感應取得的完整內容相符仍可完成驗證；若明確讀到不符內容則 MUST 回報驗證失敗。尚未重新感應時 MUST 顯示「等待重新感應驗證」；已送出寫入但未取得足夠證據時 MUST 顯示「結果未知／尚未驗證」。驗證階段 MUST 僅讀取，不自動補寫。

#### Scenario: 完整驗證成功

- **WHEN** 使用者移開並重新感應目標，其新 UID 與全部預期 block 0 內容一致
- **THEN** 系統顯示 UID 複製完成與所用模式，並說明門禁可用性尚須另行確認

#### Scenario: 同次連線讀回失敗後完成驗證

- **WHEN** 寫入後連線中斷，但使用者重新感應的 UID 與全部預期內容一致
- **THEN** 系統以重新感應的結果完成驗證，不重新寫入

#### Scenario: UID 相同但其他內容不符

- **WHEN** 重新感應的 UID 相符，但 block 0 其他位元組不符
- **THEN** 系統回報驗證失敗，不宣稱複製成功

#### Scenario: 尚未重新感應

- **WHEN** 已寫入並讀回相符，但使用者尚未移開並重新感應目標
- **THEN** 系統只顯示待驗證，不以既有 UID 快照宣稱完成

### Requirement: 中止與生命週期

系統 MUST 提供取消，並在等待逾時、畫面關閉、App 退到背景、NFC 關閉或操作資源被釋放時撤銷待命與過期操作；每個等待階段 MUST 在 30 秒未完成時結束。中止後到達的舊結果 MUST NOT 更新新操作或重新啟動寫入。回到前景時 MUST 只依一般讀卡條件恢復感應，不恢復複製待命。

系統確認仍在準備／等待階段且取消成功時，MUST 保證不再寫入；一旦操作已進入寫入階段，中止時 MUST 說明結果可能未知，MUST NOT 聲稱卡片未修改或已自動還原。所有卡片 I/O MUST 有有限的等待及清理機制，且不得阻塞介面操作。

#### Scenario: 待命期間取消或離開

- **WHEN** 操作仍在準備／等待階段，使用者取消、關閉畫面、切到背景、關閉 NFC 或等待逾時
- **THEN** 系統撤銷本次操作，之後靠近的卡片不會被該操作寫入

#### Scenario: 寫入後中止

- **WHEN** 操作已進入寫入階段但尚未完成驗證時，操作遭取消或生命週期中止
- **THEN** 系統顯示結果未知／尚未驗證，不自動重寫或宣稱還原

#### Scenario: 舊操作結果晚到

- **WHEN** 使用者已取消並啟動新操作，舊操作才回報結果
- **THEN** 舊結果不影響新來源、狀態或成功訊息

#### Scenario: 回到前景

- **WHEN** App 從背景返回且讀卡畫面仍開啟
- **THEN** 一般讀卡按原規格恢復，複製必須由使用者重新啟動

### Requirement: 重試與資料保存範圍

對仍可存取且相容的目標，系統 MUST 允許使用者重新啟動操作；重試 MUST 重新檢查來源與目標，不沿用過期的可寫判定。系統 MUST 說明無法保證卡片永久可重寫或寫入後可還原。來源／目標 block 0 與操作狀態 MUST 僅保留於本次操作記憶體，不加入 UID 歷史、匯出或持久儲存。

#### Scenario: 再次複製不同來源

- **WHEN** 使用者重新選擇不同來源，並使用仍可存取的相容目標
- **THEN** 系統重新執行資格與資料檢查，再提供一次寫入及驗證

#### Scenario: 操作結束後的資料

- **WHEN** 操作結束或讀卡畫面關閉
- **THEN** 來源／目標 block 0 不出現在持久歷史或匯出中，記憶體中的操作資料予以清除
