## Why

既有 `nfc-card-reader` 已能讀取門禁卡 UID，但使用者仍需其他工具才能把自己有權複製的卡號寫入實體備份卡。本次新增 Android 手機上的 UID 複製流程，明確界定支援條件與驗證結果，讓使用者知道卡號是否寫入成功，以及它與完整門禁卡複製的差異。

## What Changes

- **新增「複製到魔術卡」流程**：從 NFC 讀卡機選定來源卡後，由使用者明確啟動複製；重新感應來源卡取得複製資料，再提示移開來源卡、靠近目標卡。一般讀卡不額外驗證金鑰或讀取扇區。
- **以實際相容性界定支援**：來源與目標皆限 4-byte UID、手機可透過 MIFARE Classic 存取的相容卡型；目標限已驗證可用標準寫入方式改寫 block 0 的 gen2/CUID 卡。手機有 NFC 或商品標示 CUID 都不等於相容；gen1a、7／10-byte UID、其他技術及未驗證卡型不在支援範圍。
- **明確區分兩種複製結果**：來源完整 block 0 可讀且與目標卡型相容時，驗證內容後複製整塊；來源驗證失敗或 block 0 不可讀時，提供「僅複製 UID」模式，保留目標原有非 UID／BCC 位元組，不以佔位值杜撰廠商資料。此模式須能讀取並驗證目標 block 0，且不得宣稱完整複製來源資料。
- **寫入前檢查、每次操作只寫一次**：檢查目標卡型、UID 長度、sector 0 預設金鑰存取能力及待寫資料；來源與目標 UID 相同時不寫入，提示更換目標或進行唯讀核對。失敗後須由使用者重新啟動，不因卡片持續靠近而連續重寫。
- **分階段驗證**：先嘗試讀回並比對完整預期 block 0，再要求移開並重新感應目標卡，核對新讀到的 UID 與 block 0。只有兩者皆相符才顯示「UID 複製完成」；中斷或資料不足時顯示「尚未驗證／結果未知」，不誤報成功。
- **補齊中止與錯誤行為**：取消、逾時、關閉讀卡畫面、App 退到背景或 NFC 關閉時撤銷待命寫入；回到前景只恢復一般讀卡。區分金鑰驗證失敗、相容性不足、卡片移開、寫入失敗與驗證不符，不從單次失敗推斷卡片必為 gen1a 或普通卡。
- **支援重新嘗試，但不保證還原**：仍可存取的相容卡可再次操作；已發出的寫入無法保證取消或復原，不承諾永久可重寫。

### 範圍與限制

- 僅供複製使用者有權複製的卡；只處理 block 0，不讀寫其他資料區塊或金鑰／存取條件，不提供金鑰破解。
- UID 複製成功不代表門禁必定可用；是否還驗證加密資料或其他卡片特徵，需在有權使用的讀卡設備上另行確認。
- 僅 Android 提供此功能；一般讀卡、歷史紀錄、剪貼簿及 Windows（Tauri）可見性維持原行為。

## Capabilities

### New Capabilities

- `nfc-card-clone`: 明確啟動的來源資料取得、相容性檢查、完整 block 0／僅 UID 兩種模式、單次寫入、重新感應驗證、操作中止及可判定的錯誤回報。

### Modified Capabilities

（無。`nfc-card-reader` 的一般讀卡仍只取得 UID 與卡片探索資訊，不讀取扇區；block 0 存取只屬於使用者明確啟動的 `nfc-card-clone` 流程。）

## Impact

- **前置依賴**：沿用已實作的 `nfc-card-reader`；其規格仍位於另一個進行中的 change，整合／歸檔時須先確立 reader 主規格，再整合本功能，不修改該 change 的任務狀態。
- **Android 原生**（`NfcPlugin.java`）：沿用 Capacitor 與 Reader Mode；新增來源準備、單次寫入、唯讀驗證與生命週期管理。所有卡片 I/O 在非主執行緒處理，原生端保留操作狀態並再次驗證輸入。
- **前端**：`src/services/nfcClone.ts` 提供型別、資料驗證與插件封裝；`nfcReader.ts` 僅增補可選的探索資訊；`App.vue` NFC 彈窗加入分階段操作與結果提示。API、事件格式及位元組處理細節見 `design.md`。
- **依賴與資料**：沿用 Android SDK，不新增第三方套件或權限；複製資料僅存於本次操作記憶體，不加入讀卡歷史或匯出資料，無儲存格式遷移。
- **驗收**：純函式與狀態流程自動檢查，加上真實 Android 手機／卡片的相容性、中斷與重新感應測試；未完成實機驗證前不宣稱支援特定組合。
- **版本與發布**：功能實作完成後才依工作區規範同步七處版號與 `avd_s/publish_all.ps1` 預設發布說明；本次文件優化不進版，`all.ps1` 由使用者手動執行。
