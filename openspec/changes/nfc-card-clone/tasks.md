## 1. 相容性與整合前置

- [ ] 1.1 建立支援卡型的 profile 與實機驗收紀錄格式，明列 UID 長度、MIFARE Classic type／size、探索資訊、block 0 格式與手機／目標卡型；驗證每個開放寫入的 profile 都有格式依據，並把未完成實測的組合標成待驗證，不宣稱可用。
- [ ] 1.2 核對 `nfc-card-reader` 的既有程式與規格依賴；驗證普通讀卡仍只取得 UID／探索資訊，沿用 Capacitor Reader Mode 與 `tagDiscovered`，不加入 block 0 預讀或 NFC intent filter，並記錄整合／歸檔順序。

## 2. 原生資料規則與來源準備

- [ ] 2.1 抽出不依賴 Android I/O 的原生資料規則：4-byte UID／16-byte block 0 驗證、BCC、profile 相容性、完整模式及保留目標 bytes 5–15 的 UID 模式；以既有 JUnit 驗證前導零、錯誤長度／BCC／UID、模式不相容及所有非 UID bytes 保留，禁止佔位補值與靜默降級。
- [ ] 2.2 `NfcPlugin.java` 實作 `armCloneSource` 與原生來源快照，明確啟動後重新感應來源，再有限次以預設金鑰讀 block 0；驗證 UID 不符／移卡／取消不會改換來源，存取限制才提供 UID 模式，`cloneSourceReady` 帶正確操作識別碼與可用模式。
- [ ] 2.3 實作單一背景 I/O executor、連線 `finally` 清理及獨立 5 秒 watchdog；以可替換的卡片 I/O 測試介面驗證阻塞、例外及取消都會清理且不阻塞 UI，並確認沒有在主執行緒呼叫卡片 I/O。

## 3. 單次寫入、驗證與生命週期

- [ ] 3.1 實作 `armCloneWrite`、`disarmCloneWrite`、requestId 與一次性原生狀態機；用測試替身驗證重複感應／並行回呼至多呼叫一次寫入，舊 requestId 無效，來源與目標 UID 相同時寫入次數為零。
- [ ] 3.2 寫入前驗證目標技術、UID 長度、profile、sector 0 預設金鑰及原始 block 0，原生以來源快照組出預期資料；以測試替身確認任一檢查失敗都不呼叫寫入，通過時只寫 block 0，不寫資料區或 sector trailer。
- [ ] 3.3 實作 `armCloneVerify`、寫後完整區塊比較與 `awaiting-verification` 唯讀階段；同 UID 路徑只有存在獨立完整來源預期資料時才可核對，結果標示既有資料相符，不稱寫入成功；驗證舊 UID 快照不能判成功、相同 UID 但其他 byte 不符會失敗，同次連線讀回中斷後可用新的探索 UID＋完整 block 0 完成驗證，全程不得自動重寫。
- [ ] 3.4 實作各等待階段 30 秒期限，以及取消、`stopScan`、彈窗關閉、Activity pause、NFC 關閉、插件銷毀的原生撤銷；測試原子寫入邊界之前取消成功則零寫入、邊界之後中止則保守回報未知，恢復前景只恢復普通讀卡，遲到事件不影響新操作。
- [ ] 3.5 完成 `cloneResult` 的狀態／階段／錯誤與資料清理；測試驗證失敗、相容性不足、移卡、I/O 失敗、驗證不符及結果未知各自可區別，終止後清除來源／目標快照、拒絕再次 `armCloneVerify`，且不記錄 block 0 到持久資料或一般 log。

- [ ] 4.1 新增 `src/services/nfcClone.ts` 的型別、插件封裝及結果呈現邏輯；`nfcReader.ts` 如需增補探索資訊須保持可選且不改普通讀卡格式。以 Vitest 驗證 listener 先註冊再待命、過期結果忽略、終止清理與錯誤訊息映射，不接受前端任意 block 0 作為寫入依據。
- [ ] 4.2 在 `App.vue` 加入 Android 限定的來源準備、模式選擇、等待目標、寫入及重新感應驗證畫面；驗證來源固定、模式與覆寫範圍可見、來源移開提示、取消／逾時提示、相同 UID 不寫入、明確唯讀核對顯示既有資料相符而非複製完成，以及不可用狀態；Windows／非 Android 不顯示入口。
- [ ] 4.3 對齊前端與原生生命週期，關閉彈窗及卸載時撤銷操作並移除 listener；以受控事件測試背景往返、舊成功事件晚到、快速關閉重開等情境，不把未知結果顯示為成功，不把複製目標事件寫進普通讀卡歷史。

## 5. 自動與實機驗收

- [ ] 5.1 執行 `npm test`、`npm run build`，以及 Android 的 `gradlew.bat :app:testDebugUnitTest :app:compileDebugJavaWithJavac`；完成條件為全部通過，原生資料／狀態測試與既有讀卡測試皆有執行，且修改檔案符合 CLAUDE.md 編碼規範。
- [ ] 5.2 在真實支援手機與可犧牲的授權測試卡上驗證兩種模式；記錄來源／目標 profile、寫前／寫後完整內容、移開重新感應的 UID，以及相同 UID 不寫入與不同來源重新複製。只有完整驗證通過的組合可標記為已支援，不以模擬器或編譯代替實機結果。
- [ ] 5.3 實機驗證非支援手機／卡型、7-byte 來源及目標、非預設金鑰、普通唯讀卡、寫入被拒與驗證不符；逐項記錄結果，確認未把單次失敗診斷為 gen1a 或永久損壞，也未誤報成功。
- [ ] 5.4 實機驗證來源讀取時移卡、寫入／讀回時移卡、驗證等待逾時，以及各階段取消、關閉彈窗、切背景、關閉 NFC；逐項確認取消成功且尚未進入寫入階段時零寫入；可恢復的讀回中斷留在等待唯讀驗證，寫入開始後的取消／生命週期中止／逾時則以未知終止並清除資料，恢復後不自動重寫。
- [ ] 5.5 回歸普通讀卡：4／7／10-byte UID 顯示、剪貼簿、歷史去重與重啟保存、無 NFC 提示、背景恢復及 Windows 入口隱藏；驗證未啟動複製時不執行金鑰驗證或 block 0 I/O，複製資料未進入歷史／匯出。
